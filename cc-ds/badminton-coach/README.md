# Badminton Coach

A local-first badminton technique review app. Upload a short solo clip, and the app:

- tracks the athlete's 17-point body skeleton with YOLO pose,
- recognizes overhead, lunge, and ready-stance **movement episodes**,
- measures form indicators and flags patterns outside versioned coaching thresholds,
- renders an annotated skeleton video with an issue timeline,
- writes a grounded coaching review, and
- recommends exercises from a curated catalog.

The review is generated by Claude from structured pose findings when an Anthropic key is
available. Without a key, a deterministic local template produces the same shape of report, so
the app works end to end offline apart from the pose model weights.

For the current implementation status, environment caveats, and a move-to-another-machine
checklist, see [HANDOFF.md](HANDOFF.md).

> **Important:** YOLO pose detects bodies and keypoints, not badminton shots. The app does not
> classify smashes, clears, drops, serves, or tactics, and it is not a medical or injury tool.

## Quick start

Requirements: macOS or Linux, Node.js 22+, ffmpeg/ffprobe, and [uv](https://docs.astral.sh/uv/).

```bash
brew install ffmpeg uv          # macOS
npm install
cd apps/api && uv sync && cd ../..
cp .env.example .env            # optional; defaults already work
# If the API runs somewhere other than 127.0.0.1:8000:
# cp apps/web/.env.example apps/web/.env.local
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The API runs at
[http://127.0.0.1:8000](http://127.0.0.1:8000), with interactive docs at `/docs`.

The first real analysis downloads `yolo11n-pose.pt` from Ultralytics. If GitHub is blocked on
your network, download the weights another way and set `POSE_MODEL=/absolute/path/to/yolo11n-pose.pt`
in `.env`.

### Try the app without model weights

The synthetic backend exercises the whole product with a deterministic athlete:

```bash
npm run dev:demo
```

Upload [fixtures/synthetic-athlete.mp4](fixtures/synthetic-athlete.mp4) in the UI. It produces a
ready-stance fault, two readiness exercises, an annotated video, and a template review. See
[fixtures/README.md](fixtures/README.md). This mode does not need model weights, an API key, or
network access.

## Recording a useful clip

- One athlete only; doubles and bystanders are rejected or warned about.
- 10–60 seconds, full body from head to feet, with margin around the racket arm.
- Stable camera on a tripod or propped phone; no zoom, cuts, or camera movement.
- Even light, fitted clothing, and a plain background.
- One or two clear repetitions plus the ready stance between them.
- **Side view:** best for lunge depth, torso lean, and overhead reach.
- **Front view:** best for stance width and knee-over-foot alignment.
- Select the camera angle and racket hand in the upload form. Mark clips that are mirrored.

## How it works

```text
upload -> ffprobe validation -> ffmpeg normalization (15 fps, max 1280 px)
       -> YOLO pose + ByteTrack -> one-athlete selection -> gap fill + One Euro smoothing
       -> movement episode segmentation -> 2D metrics -> threshold rules
       -> annotated H.264 video + result.json -> Claude / template review
       -> curated exercise plan
```

- **Jobs:** SQLite queue and a single worker process. No Redis or Celery.
- **Storage:** `data/analyses/<uuid>/` with the normalized clip, annotated video, thumbnail,
  pose artifact, and result JSON.
- **API:** `/api/v1/analyses` for upload/status/result/video, plus health and report retry.
- **Contract:** Pydantic is the source of truth; JSON Schema and TypeScript types are generated
  into `contracts/` and `apps/web/src/lib/generated/`.
- **LLM grounding:** the model sees only structured measurements and fault IDs, never video or
  keypoints. It may select only exercises from a filtered catalog. Exercise dosage, instructions,
  and safety text always come from the catalog. Invalid IDs, banned medical/stroke language, and
  unsupported measurements trigger one retry, then the local template. Claude requests also enable
  the server-side refusal fallback, with the local template as the final safety net.

## Configuration

Copy `.env.example` to `.env` and edit as needed.

| Variable | Default | Purpose |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `http://127.0.0.1:8000` | Browser -> API origin |
| `DATA_DIR` | `./data` | SQLite DB and analysis artifacts |
| `MAX_UPLOAD_MB` | `200` | Upload limit |
| `ANALYSIS_FPS` | `15` | Frame rate used for pose inference |
| `VIDEO_MAX_WIDTH` | `1280` | Normalized analysis width |
| `POSE_BACKEND` | `ultralytics` | `ultralytics` or `fake` |
| `POSE_MODEL` | `yolo11n-pose.pt` | Ultralytics checkpoint name or local path |
| `POSE_DEVICE` | `auto` | `mps`, `cuda`, or `cpu` |
| `REPORT_PROVIDER` | `anthropic` | `anthropic` or `template` |
| `ANTHROPIC_API_KEY` | empty | Enables Claude-written reviews |
| `COACH_ANTHROPIC_MODEL` | `claude-opus-5-5` | Report model; prefixed to avoid colliding with Claude Code's own env |
| `COACH_ANTHROPIC_EFFORT` | `medium` | Claude effort level |

If report generation fails, the analysis still completes with a template review and the failure
is recorded. Use the retry button in the review panel or `POST /api/v1/analyses/{id}/report/retry`.

## Testing

```bash
cd apps/api && uv run pytest -q && uv run ruff check app tests
cd ../.. && npm run typecheck
npm run contracts:check       # after committing the generated files
npm run build
```

The test suite uses the fake pose backend and a real ffmpeg render. It covers media validation,
smoothing, episode segmentation, quality gates, view gating, fault thresholds, catalog integrity,
report validation, API upload/status/result, HTTP Range video delivery, report retry, and contract
drift.

## Model licensing

The default pose backend uses **Ultralytics YOLO**, which is **AGPL-3.0**. Local/open-source use is
lower risk; a public or commercial hosted service normally requires an Ultralytics Enterprise
License or a switch to an Apache-2.0 pose stack. The `PoseBackend` boundary in
`apps/api/app/pipeline/pose/` is intentionally small so RTMPose/MediaPipe can replace Ultralytics
without changing the analysis layer. Model weights carry their own license; check before
redistributing them.

## Privacy and deployment

This MVP is designed for a local, single-user machine. It has no authentication and binds the API
to `127.0.0.1`. Do not expose it directly to the internet with personal video.

Before public deployment, add authentication and per-user ownership, upload quotas, a retention /
deletion policy, object storage for media, Postgres, a real job queue, and an explicit consent
flow for identifiable people (especially minors).
