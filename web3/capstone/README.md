# Capstone · 综合项目

> 建议学时：1 周以上（实践 10 : 理论 0）　｜　截至 2026-11
> 前置：M0–M18 至少完成 Part I–III；建议先完成 M5、M6、M9、M10。

Capstone 是把课程知识串起来的一次完整交付。它不要求你做一个"改变世界"的协议，而要求你证明自己能够：

1. **定义问题**：说清楚要解决什么问题、为什么需要区块链、成功指标是什么；
2. **设计与实现**：写出可读、可测试、可部署的代码或可复现的研究；
3. **评估风险**：主动寻找自己的系统会怎样失败，而不是只展示它如何成功；
4. **清楚表达**：让一个没参与开发的同学能在 30 分钟内理解你的设计、证据与结论。

## 1. 三条路线（三选一）

### A. 协议构建（Protocol Build）

设计并实现一个小型 DeFi 协议。推荐题目：

- 带 TWAP 预言机的超额抵押借贷市场；
- 带 hooks 的恒定乘积 AMM（手续费分档、限价单、或 LP 激励）；
- 简化版 CDP 稳定币（开仓、还款、清算、稳定费）；
- 收益代币化（本金 / 收益分离）的最小实现。

**必须交付**

| 交付物 | 要求 |
|---|---|
| 合约 | Solidity ^0.8.x；核心逻辑不超过 600 行；无未说明的管理员后门 |
| 测试 | Foundry 单元测试 + 至少 1 个不变量测试；核心路径覆盖率 ≥ 90% |
| 前端 | 最小可用页面：连接钱包、读状态、发交易（本地 Anvil 即可） |
| 经济模型 | 参数表、激励来源、极端情景下的敏感性分析 |
| 自审报告 | 按 [`docs/audit-report-template.md`](../docs/audit-report-template.md) 写 |
| README | 架构图、部署步骤、演示脚本、已知限制 |

**评分重点**：正确性、不变量是否真的成立、风险意识，而不是 UI 精美程度。

### B. 金融研究（Financial Research）

对一个真实协议做完整研究。推荐对象：Aave、Uniswap v3、Maker/Sky、Ethena、Pendle、Lido、EigenLayer 等。

**必须交付**

| 交付物 | 要求 |
|---|---|
| 研究报告 | ≥ 8000 字；机制、代币经济、链上数据、风险、估值五部分 |
| 数据看板 | Dune / Flipside 查询，或自建索引器 + 图表；附可复现 SQL / 代码 |
| 估值模型 | 至少一个可复现的 DCF、P/F、P/S 或供给-需求模型，含敏感性分析 |
| 风险清单 | 按 [`docs/risk-assessment-template.md`](../docs/risk-assessment-template.md) 写 |
| 答辩 | 15 分钟讲解 + 10 分钟问答 |

**评分重点**：论点是否有数据支撑、是否区分"协议收入"与"代币价格"、是否识别尾部风险。

### C. 基础设施（Infrastructure）

构建一个开发者工具或链上基础设施。推荐题目：

- 测试网 / 主网分叉上的 MEV 机器人（套利或清算）；
- 自建事件索引器（监听 → 解码 → SQLite/Postgres → 指标 API）；
- ERC-4337 智能账户 + Paymaster 的最小实现；
- 基于 Circom / Noir 的 ZK 应用（如 Merkle 成员证明）；
- 交易模拟器 / gas 分析器 / 合约存储布局可视化工具。

**必须交付**

| 交付物 | 要求 |
|---|---|
| 代码仓库 | 清晰的模块划分、配置示例、一键启动脚本 |
| 技术文档 | 架构、数据流、失败模式、性能与安全分析 |
| 演示 | 在本地链或测试网完成一次端到端演示 |
| 测试 | 关键路径有自动化测试；外部依赖有 mock 或降级方案 |
| 风险分析 | 密钥管理、RPC 依赖、重放 / 竞态、监控与告警 |

**评分重点**：可靠性、可观测性、对失败模式的诚实分析。

## 2. 建议时间线（4 个阶段）

| 阶段 | 时间 | 产出 | 检查点 |
|---|---|---|---|
| P0 选题与范围 | 第 1–2 天 | 一页 proposal：问题、方案、成功指标、风险 | 能否用三句话说清"为什么需要区块链" |
| P1 最小闭环 | 第 3–5 天 | 能跑通的主路径（合约 + 测试 / 数据管道 / 研究框架） | 端到端演示一次，哪怕很粗糙 |
| P2 加固与评估 | 第 6–8 天 | 测试、压力测试、敏感性分析、风险清单 | 主动找出至少 3 个失败场景 |
| P3 文档与答辩 | 第 9–10 天 | README、报告、看板、演示脚本 | 外人能按文档复现 |

> 建议在 P1 结束时做一次"预演"：把当前版本讲给同学听，记录他们提出的问题。P2 的优先级由这些问题决定。

## 4. 评分维度

| 维度 | 权重 | 合格（60%） | 良好（80%） | 优秀（100%） |
|---|---|---|---|---|
| 正确性 | 30% | 主路径能跑 | 边界条件有测试 | 不变量 / 形式化性质被验证 |
| 设计质量 | 25% | 能完成功能 | 模块清晰、参数有依据 | 权衡有数据支撑，能解释为何不选另一方案 |
| 安全 / 风险意识 | 20% | 知道常见漏洞 | 主动测试攻击场景 | 有威胁模型、监控与应急方案 |
| 文档与表达 | 15% | 能按文档跑起来 | 结构清晰、图表有效 | 能让非专家理解核心权衡 |
| 创新 | 10% | 复现课程内容 | 有独立改进 | 提出并验证一个有价值的新问题 |

**扣分项**：无法复现、隐瞒已知失败、把"审计过"当作安全证明、用真实资产做实验、抄袭未注明来源。

## 6. 合规章节

- 所有链上实验仅在**本地链（Anvil）或测试网**进行；
- 不使用真实资产、不进行公开募资、不提供投资建议；
- 中国大陆禁止虚拟货币交易及相关业务活动；本课程以学术与工程教学为目的；
- 涉及用户数据时，遵守最小化收集与脱敏原则；
- 引用第三方代码、数据、图表时注明来源与许可证。

## 8. 常见问题

**Q：可以组队吗？**
建议 1–2 人。组队时每人必须有可独立验证的模块，并在 README 中写清分工。

**Q：必须部署到测试网吗？**
路线 A/C 建议至少在本地区块链上完成端到端演示；测试网部署是加分项，不是硬性要求。

**Q：可以用 AI 辅助编程吗？**
可以。你必须理解并能为每一行关键代码负责；提交时注明使用了哪些工具、哪些部分由工具生成、你如何验证。

**Q：没有真实链上数据怎么办？**
路线 B 可以使用公开的 Dune / Etherscan / The Graph 数据；路线 C 可以在本地链生成数据。关键是说明数据来源、时间窗口与偏差。
