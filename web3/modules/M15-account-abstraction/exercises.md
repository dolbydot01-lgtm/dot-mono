## 参考答案

### A1

六个限制：单点故障（无私钥恢复/轮换）；签名算法固定（不支持 Passkey/多签/后量子）；不能批量；不能代付 gas；没有权限细分/会话密钥；没有消费限额/延迟；钓鱼面大（approve/permit）。账户抽象解决"验证与执行可编程"，从而支持恢复、多签、Passkey、批量、代付、限额、会话密钥；但它不解决私钥/签名者被钓鱼、合约 bug、链上隐私、MEV、跨链信任等。

把资产转到合约钱包只是"换了个账户"，如果没有可编程的验证逻辑、恢复、Paymaster、Bundler 支持，仍然不是完整的 AA；而且新地址会丢失原有地址的历史/ENS/社交关系。7702 的价值之一就是保留原地址。

### A2

- UserOperation：用户意图的结构化描述（sender、nonce、callData、gas、paymaster、signature）。
- Bundler：收集、模拟、打包 UserOp，支付 L1/L2 gas，赚取费用。
- EntryPoint：链上单例，验证并执行 UserOp，统一结算。
- Account：智能合约账户，验证签名、支付 prefund、执行调用。
- Paymaster：代付 gas，可收 ERC-20，需在 EntryPoint 存款/质押。
- Aggregator：聚合多个账户的签名（可选），降低验证成本。

Bundler 模拟是为了避免打包必然失败的 op（签名错、prefund 不足、Paymaster 过期、nonce 冲突），否则 Bundler 白付 gas。模拟不能完全避免失败：模拟与上链之间状态会变（余额、价格、allowlist、nonce、L1 baseFee），所以仍需重试、失败隔离与保守 gas 估算。

### A3

流程：钱包构造并签名 UserOp → Bundler 模拟 → 打包 `handleOps` → EntryPoint 调 `validateUserOp`，账户验证签名并补足 prefund → 若用 Paymaster，调 `validatePaymasterUserOp` → 执行 `callData` → 调 `postOp` → EntryPoint 按实际 gas 结算、退款 → Bundler 收费。

1. **验证失败**：EntryPoint 拒绝该 op，不执行、不扣账户 gas；nonce 不变（或按实现回滚）；Paymaster 存款不变；Bundler 承担模拟/打包成本，可能损失 gas。账户若已转 prefund，会退回（具体以实现为准）。
2. **执行 revert**：验证已通过，nonce 已递增，gas 按实际消耗收取；Paymaster 存款被扣；Bundler 仍获得费用；`callData` 的目标状态回滚，但 op 的 nonce/gas 记账不回滚。钱包应提示"交易失败但已扣 gas"。

### A4

Paymaster 在 EntryPoint 有存款，EntryPoint 才能在其验证通过后扣 gas；质押用于存储访问规则/防 Sybil/防 Bundler 被 DoS。收 ERC-20 的风险：代币价格波动、预言机操纵、代币转账失败/重入、`postOp` gas 不足、用户用垃圾代币支付、合规/制裁。

`postOp` revert 可能导致该 op 失败/被拒，Paymaster 仍可能被收取验证 gas；具体行为取决于 EntryPoint 版本与 `postOp` 的 gas 限制。Paymaster 必须保证 `postOp` 不 revert，或预留足够 gas/回退逻辑。

验证阶段访问存储会触发 ERC-7562 的质押/声誉/节流规则：因为 Bundler 无法在链上模拟所有存储访问，恶意 Paymaster 可以构造大量冷存储读取来 DoS Bundler；质押让恶意行为有成本，声誉/节流限制滥用。

### A5

授权列表字段：`chain_id, address, nonce, y_parity, r, s`。签名摘要：`keccak256(0x05 || rlp([chain_id, address, nonce]))`。上链后 EOA 代码设为 `0xef0100 || address`；调用 EOA 时执行 `address` 的代码，但上下文仍是 EOA。

`chainId=0` 表示授权在所有链上有效；同一 nonce 在另一条链未使用时，授权可被重放，在另一条链上也设置委托。必须绑定具体 chainId 与 nonce。

7702 只提供"代码委托"，不提供 EntryPoint/Bundler/Paymaster 的完整栈；它常与 4337 组合（EntryPoint v0.8 支持 7702 账户）。所以 7702 不是完整 AA：它没有统一的 UserOp 生命周期、代付、聚合、模拟与结算。

### A6

- **社交恢复**：解决私钥丢失；引入 guardian 被钓鱼/收买、恢复请求被伪造、timelock 被绕过等攻击面。降低风险：guardian 独立、阈值、48h timelock、恢复请求显示完整新 owner/chainId、旧钥匙可取消、多因素。
- **会话密钥**：解决每次操作都要主钱包签名的 UX 问题；引入临时钥匙泄露、权限过宽、撤销不及时。降低风险：最小权限（合约/函数/额度/过期）、可撤销、限额、监控、把高风险操作留给主钥匙。
- **Passkey**：解决助记词/密码问题，抗钓鱼；引入设备丢失、平台账号被攻破、云同步被劫持、P-256 验证成本/兼容性。降低风险：多设备、社交恢复、硬件备份、显示交易详情、绑定 origin。

组合建议：Passkey 作为主签名（设备内），智能账户 + 社交恢复作为后备，会话密钥给 dApp 有限权限，Paymaster 代付 gas；高风险操作要求主 Passkey + timelock。

### A7

- 原生 Rollup 桥：验证 L1 上的 Rollup 状态/证明；信任 L1 共识 + Rollup 安全；失败时提款延迟/升级治理。
- 轻客户端桥：验证对手链头/签名；信任对手链共识 + 同步委员会；失败时可能被共识攻击/轻客户端 bug。
- 乐观桥：先接受，挑战期欺诈证明；信任至少一个诚实 watcher；失败时挑战期资本/审查。
- ZK 桥：有效性证明；信任证明系统/电路/可信设置；失败时电路 bug 可伪造消息。
- 验证者/多签桥：M-of-N 签名；信任验证者不被攻破/不串谋；失败时密钥泄露。
- 流动性网络：做市商在目标链放款；信任做市商信用/流动性；失败时流动性枯竭/审查。

TVL 高只说明"锁在桥里的钱多"，不说明验证者去中心化、密钥管理、代码审计、限额、监控、升级治理；TVL 高反而提高攻击收益。Ronin 的 TVL 很高，但 5-of-9 密钥被社工攻破。

### A8

- CCIP：Router/OnRamp/OffRamp/CommitStore/TokenPool + DON + RMN；信任 Chainlink DON + RMN 阈值诚实 + 合约正确性；可暂停/否决。
- LayerZero：Endpoint + ULN + DVN + Executor；应用自选 DVN 集合/确认数；安全取决于配置，单 DVN 接近单点信任；OFT 用 burn/mint 或 lock/unlock。
- Wormhole：19 Guardian，13-of-19 签署 VAA；信任 Guardian 阈值 + 合约正确性；2022 年 Solana 合约签名验证 bug 导致 120k wETH 被凭空铸造，说明代码 bug 可以绕过 Guardian 假设。

LayerZero 的"可配置"意味着协议不强制一个固定验证者集合；应用可以选择自己的安全栈，但也可能配置得很弱。Wormhole 事件说明：验证者集合没被攻破，不等于桥安全；实现 bug 同样是致命信任假设。

### A9

Intent：用户签名"想要的结果"（限价、deadline、目标链、收款地址）；solver 竞争填充：目标链先垫付，源链领取，桥/流动性结算，失败退款/罚没。ERC-7683 标准化订单结构与结算接口。

改善：一次签名、自动选路、gas 抽象、失败回滚、更好的价格/速度。新风险：solver 不 fill/审查/延迟；adverse selection/MEV；源链回滚/目标链重组；退款失败；隐私泄露；合规 choke point。

质押与竞争能降低但不消除风险：solver 可能串谋、质押不足、攻击结算合约、利用信息优势；需要仲裁、保险、限额、透明度与多 solver 竞争。

### B1

1. `70,000 + 50,000 + 22,000 + 12,000 + 6,000 = 160,000 gas`；prefund `160,000 × 25 gwei = 4,000,000 gwei = 0.004 ETH`。
2. `effective = min(25, 9 + 1.5) = 10.5 gwei`。
3. 实际 `61,000 + 44,000 + 22,000 + 11,000 + 5,000 = 143,000 gas`；charge `143,000 × 10.5 gwei = 1,501,500 gwei = 0.0015015 ETH`；refund `0.004 − 0.0015015 = 0.0024985 ETH`。
4. `0.0015015 / 0.004 = 0.375375 = 37.5375%`。
5. gas 成本 `0.0015015 × 3,000 = $4.5045`；收入 $4；亏损 `$0.5045`。
6. 10 笔收入 `10 × 0.0015015 = 0.015015 ETH = $45.045`；L1 成本 `400,000 × 12 gwei = 4,800,000 gwei = 0.0048 ETH = $14.40`；毛利 `$30.645`。

### B2

1. `3 × 25,000 = 75,000 gas`；3 个都已存在，退款 `3 × 12,500 = 37,500`；净 `75,000 − 37,500 = 37,500 gas`。
2. 1 个新建：基础 `3 × 25,000 = 75,000`，新建额外 `25,000`，2 个已存在退款 `2 × 12,500 = 25,000`；净 `75,000 + 25,000 − 25,000 = 75,000 gas`。
3. 最多 20 次（每条链一次，前提是 nonce 未使用）。修复：授权绑定具体 chainId（不要用 0）、绑定 nonce、钱包 UI 显示链与委托目标、对跨链授权做 domain separation。

### B3

1. 5-of-9：`5 × 400,000 = $2,000,000`；成本/TVL `2M/800M = 0.25%`；潜在利润 `$800M − $2M = $798M`。13-of-19：`13 × 400,000 = $5,200,000`；`5.2M/2B = 0.26%`；利润 `$1.9948B`。
2. 日限额 $20M：5-of-9 需要 `800/20 = 40 天`；13-of-19 需要 `2000/20 = 100 天`。
3. 单密钥 $1M：5-of-9 攻击成本 `$5M`，`5/800 = 0.625%`；13-of-19 `$13M`，`13/2000 = 0.65%`。
4. 忽略：社会工程/内部人、密钥托管方式、验证者串谋、代码 bug（Wormhole）、升级多签、跨链流动性、监控/暂停、保险、攻击者时间成本、TVL 变动、日限额可被多地址/多天绕过。验证者多不等于安全：如果密钥由同一组织/同一云托管，或阈值签名实现有 bug，数量不提供独立安全边际；Ronin 的 5-of-9 就是例子。

### B4

1. 严格顺序：500 条（501–1000）被阻塞，直到 500 到达/超时/跳过。
2. 乱序：不会队头阻塞，但依赖关系可能被破坏（如先执行"还款"再执行"借款"、先 mint 后 burn）；应用层需要 nonce/依赖图/幂等/超时退款，桥要防重放与重复执行。
3. 20 条链 × 1,000 条 = 20,000 个消息 ID（若每条链独立处理）。如果摘要不包含 `dstChainId`，同一条消息的 ID 可能在多条链上相同，导致"已处理"集合跨链碰撞或重放；必须把 `srcChainId`、`dstChainId`、`nonce`、`srcBridge`、`dstBridge` 等纳入摘要，并按链隔离存储。

### B5

`P(≥3) = C(5,3)p³(1−p)² + C(5,4)p⁴(1−p) + p⁵`。

1. `p=0.1`：`10×0.001×0.81 + 5×0.0001×0.9 + 0.00001 = 0.0081 + 0.00045 + 0.00001 = 0.00856 = 0.856%`。
2. `p=0.2`：`10×0.008×0.64 + 5×0.0016×0.8 + 0.00032 = 0.0512 + 0.0064 + 0.00032 = 0.05792 = 5.792%`。
3. 4-of-7、`p=0.1`：`C(7,4)0.1⁴0.9³ + C(7,5)0.1⁵0.9² + C(7,6)0.1⁶0.9 + 0.1⁷ = 0.0025515 + 0.0001701 + 0.0000063 + 0.0000001 = 0.0027280 ≈ 0.2728%`。
4. 如果 guardian 不独立（同一云、同一设备、同一人、同一司法辖区），真实风险高于独立模型；独立假设会低估串谋/单点故障。反过来，如果 guardian 独立且分散，模型才接近现实。

### C1

1. 基线输出：prefund `0.00408 ETH`；charge `0.001452 ETH`；refund `0.002628 ETH`；比例 `35.59%`。
2. 5 USDC、ETH $3,000：gas 成本 `$4.356`，P&L `+$0.644`。
3. 3 USDC、ETH $3,000：`3 − 4.356 = −$1.356`；5 USDC、ETH $4,000：`5 − 5.808 = −$0.808`；3 USDC、ETH $4,000：`3 − 5.808 = −$2.808`。
4. 执行失败仍收费是必要的：Bundler 已经为打包支付了 L1/L2 gas，如果失败不收费，用户可以故意提交会 revert 的 op 来消耗 Bundler 的 gas（DoS）；收费让用户承担失败成本。验证失败通常不收费，因为 op 未进入执行，Bundler 可通过模拟提前拒绝；但如果 Bundler 仍打包，成本由 Bundler 承担。

### C2

1. 场景 A：目标链检查 `dstChainId`，消息 `dstChainId=10` 与链 137 不符，拒绝。场景 B：不检查字段，但用自己的 chainId 重建摘要，签名不匹配（0/3），拒绝。场景 C：既不检查字段，也不用自己 chainId 重建摘要，消息被接受，链 137 凭空铸造 $1M——这是跨链重放漏洞。
2. 重复签名者：3 条签名都来自验证者 0，若实现只数"签名条数"就会误以为 3/3；代码按唯一 signer 去重后只有 1/3，拒绝。修复：用 `Set` 记录唯一验证者，签名验证后计数，拒绝重复/未知 signer。
3. 3 个验证者被攻破：伪造 $50M 被接受（无日限额）；日限额 $10M 时拒绝该笔，但攻击者可分多天/多地址绕过，仍需监控、延迟提款、熔断、验证者轮换。
4. 顺序 nonce：防选择性延迟/重排，但队头阻塞；乱序：灵活，但应用层要处理依赖与幂等。支付/结算类适合严格顺序；消息/事件类可乱序 + 应用层依赖图。

### C3

以 Ronin 与 Wormhole 为例：

- **Ronin**：5-of-9 验证者密钥被社工/钓鱼攻破；没有即时日限额/监控。若当时有日限额、延迟提款、异常监控、熔断，单次损失会被限制，团队有时间反应。改进：密钥硬件隔离/MPC、验证者独立、阈值提高、日限额、延迟提款、监控、轮换、保险。
- **Wormhole**：Solana 合约签名验证 bug，攻击者绕过验证铸造 120k wETH。日限额/铸造上限/异常检测能限制损失；但根本修复是形式化验证、审计、边界条件测试、不可升级/升级延迟。改进：验证逻辑审计、mint cap、监控、暂停、bug bounty、 defense in depth。

"多签=安全"的反驳：Ronin 的多签密钥被攻破；Wormhole 的 Guardian 没被攻破但代码 bug 绕过验证；Nomad 的初始化 bug 让任何人都能伪造消息。桥的安全是多维的：密钥、代码、初始化、升级、监控、经济激励，缺一不可。

### C4

参考设计：

1. **架构**：EOA 通过 7702 委托到一个经过审计的智能账户实现（保留地址/资产）；主签名用 Passkey（P-256，EIP-7951 预编译降低验证成本）；账户支持 4337 UserOp（Bundler 代发）、Paymaster 代付（USDC 或赞助）；会话密钥模块给 dApp 有限权限；guardian 恢复模块。新用户也可以直接部署智能账户，7702 用于已有 EOA。
2. **恢复**：3-of-5 guardian（设备、亲友、硬件、机构），48h timelock，旧 Passkey 可取消；恢复请求显示新 owner/chainId/委托目标；guardian 独立、多地域；可选继承/法律流程。
3. **会话密钥**：按 dApp/合约/函数白名单、每日/单笔限额、过期时间、链 ID、nonce、可撤销；高风险操作（转出全部资产、改 owner、改 guardian）必须主 Passkey + timelock。
4. **威胁与缓解**：
   - 钓鱼 7702 委托：钱包显示委托目标、模拟调用、白名单、撤销入口；
   - Passkey 设备丢失：多设备/guardian 恢复；
   - guardian 串谋：阈值、独立、timelock、监控；
   - 会话密钥泄露：最小权限、限额、撤销、异常检测；
   - Paymaster 破产/审查：多 Paymaster、备用 gas、直接付 ETH；
   - Bundler 审查：多 Bundler、强制包含/直接交易；
   - 跨链重放：chainId/nonce/domain separation；
   - 供应链/前端攻击：签名前显示完整交易、开源、审计。
5. 最难取舍：**安全与易用的平衡**。恢复越强，guardian/中心化信任越重；会话密钥越方便，权限越大；Passkey 越无感，设备/平台依赖越强；7702 保留地址越方便，恶意委托/重放风险越高。没有免费的安全，只有明确的威胁模型与用户教育。
