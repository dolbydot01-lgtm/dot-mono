## 1. 直觉：浏览器不是数据库

区块浏览器展示的是"一笔交易"：from、to、value、gas、logs。但分析师要回答的是"过去 30 天这个 DEX 的成交量是多少"、"空投后 90 天用户还在不在"、"前 10 个地址控制多少供应量"。这些问题需要**表**，而不是交易列表。

从交易到表，要经过四步：

1. **原始层**：区块头、交易、收据（status、gasUsed、logs）、trace（内部调用）；
2. **解码层**：用 ABI 把 `log.topics` / `log.data` 解码成 `Swap(sender, amount0In, amount1Out, ...)`；
3. **抽象层**：把事件整理成事实表（swaps、transfers、borrows、liquidations）与维度表（tokens、pools、labels）；
4. **指标层**：按日/池/用户聚合，计算 TVL、volume、fees、retention、HHI。

> **地址 ≠ 用户。** 一个人可以有多个地址；一个地址可以是交易所 omnibus、桥、做市商、机器人，背后是成千上万人。所有"用户数"指标都必须先回答"地址到实体的映射"。

## 2. 数据层次与索引器

| 层次 | 典型数据 | 工具 | 常见坑 |
|---|---|---|---|
| 原始层 | block、tx、receipt、log、trace | RPC、归档节点、Etherscan API | reorg、迟到区块、RPC 限流 |
| 解码层 | 事件参数、函数调用 | ABI、topic0、解码库 | 代理合约 ABI 变更、非标准事件 |
| 抽象层 | swaps、transfers、borrows、pools | SQL/dbt、流处理 | 重复事件、失败交易、内部转账 |
| 指标层 | 日成交量、TVL、留存、HHI | BI、 notebook | 口径不一致、幸存者偏差 |

**索引器的最小正确性要求：**

- **幂等**：同一区块/事件重复投递不能重复计数；用 `(txHash, logIndex)` 作为事件主键。
- **reorg 处理**：同一高度出现不同区块哈希时，回滚该高度及以上的所有事件，再应用新块。
- **最终性**：确认数不足的区块标记为"未最终确定"，指标可重算。
- **可重放**：保留原始日志与解码版本， schema 变更后可 backfill。
- **可对账**：索引结果与链上 `eth_getLogs` / 区块浏览器抽样比对。

Lab 17.2 会用一个内存事件流演示：朴素索引器把重复投递和 reorg 前的旧区块都计入，成交量虚增 16.1%；稳健索引器去重、回滚后与规范链完全对账。

## 3. 指标体系

### 3.1 TVL 与重复计算

TVL（Total Value Locked）通常定义为：

$$
\text{TVL} = \sum_{\text{协议}} \sum_{\text{资产}} \text{balance} \times \text{price}
$$

问题在于"同一份资本可以被多个协议同时计入"。三种常见机制：

1. **循环借贷**：存入 A 协议 → 借出 75% → 存入 B 协议 → 再借出 → …；
2. **LP 凭证**：ETH/USDC LP token 存入农场，农场再把 LP token 计入自己的 TVL；ETH 和 USDC 也被 DEX 计入；
3. **再质押/包装**：ETH → stETH → 再质押 → LRT → 再存入借贷；每一层都显示 TVL。

**手算示例**：1000 USDC，LTV 75%，循环存入 5 个协议：

$$
1000 + 750 + 562.5 + 421.875 + 316.406 = 3050.78\ \text{USDC}
$$

净资本只有 1000，虚增 3.05 倍；无限循环时 $1000/(1-0.75)=4000$，杠杆 4 倍。报告时应区分：

- **总 TVL（gross）**：各协议锁仓量简单加总；
- **净 TVL（net）**：剔除再存入的 borrowed funds / LP 凭证；
- **TVS（Total Value Secured）**：按安全假设覆盖的资产，可能高于或低于 TVL。

> 看到"TVL 10 亿"先问：口径是什么？是否包含重复计算？资产价格按什么时点？是否有负债端？

### 3.2 真实收入：Fees、Revenue、Earnings

| 指标 | 定义 | 例子 |
|---|---|---|
| **Fees** | 用户支付的总费用 | DEX 每笔 0.3% |
| **Revenue** | 协议留存的部分 | 0.05% 给协议金库，0.25% 给 LP |
| **Earnings** | Revenue − token incentives − 运营成本 | 扣除流动性挖矿后的净收入 |
| **Real yield** | 以真实费用分配的收益 | 不是靠增发代币 |

**手算示例**：某 DEX 日成交量 1 亿美元，费率 0.05%，协议分成 20%：

$$
\text{日 fees}=100{,}000{,}000\times0.0005=50{,}000\ \text{美元}
$$

$$
\text{日 revenue}=50{,}000\times20\%=10{,}000\ \text{美元}
\Rightarrow \text{年化}=3{,}650{,}000\ \text{美元}
$$

若 FDV 为 5000 万美元，$P/F=50{,}000{,}000/3{,}650{,}000\approx13.7$。若每天发放 8000 美元 token 激励，则净 revenue 只有 2000 美元/天，年化 73 万美元，$P/F\approx68.5$。**同样的"收入"，激励前后估值差 5 倍。**

### 3.3 活跃地址与留存

- **DAU/MAU**：日活/月活；**stickiness** = DAU/MAU。
- **队列留存（cohort retention）**：按首次使用月份分组，观察第 $t$ 周/月仍活跃的比例。
- **留存曲线**：$R(t)=N_t/N_0$；若近似指数衰减，$R(t)=p^t$，半衰期 $t_{1/2}=\ln 0.5/\ln p$。

**手算示例**：10,000 个新用户，第 1 周留存 4,000（40%），第 4 周 2,500（25%），第 12 周 1,500（15%）。若假设单一每周留存 $p=0.85$，则第 4 周预测 $0.85^4=52.2\%$、第 12 周 $0.85^{12}=14.2\%$；但同一模型会预测第 1 周 85%，与观测的 40% 矛盾。单一指数无法同时拟合"早期快速流失"与"后期长尾"，真实留存通常要用混合模型或经验曲线。

**地址 ≠ 用户**的三种偏差：

1. 一个用户多个地址（空投农民、隐私习惯）；
2. 一个地址多个用户（交易所、桥、托管）；
3. 机器人/MEV 地址高频但非人类用户。

### 3.4 持币集中度：HHI、Gini、Nakamoto

**HHI**：

$$
\text{HHI}=\sum_i s_i^2,\quad s_i \text{ 以百分比计}
$$

范围 0–10000。美国 2023 年《合并指南》把 HHI 超过 1,800 视为高度集中；不同辖区与行业的阈值不同，不能机械套用。更重要的是：这是"市场集中度"类比，不能直接等同于"治理攻击难度"。

**手算示例**：四个实体份额 40%、30%、20%、10%：

$$
\text{HHI}=40^2+30^2+20^2+10^2=1600+900+400+100=3000
$$

**Gini**：

$$
G=\frac{\sum_i\sum_j|x_i-x_j|}{2n^2\bar{x}}
$$

**手算示例**：持有量 $[90,5,3,2]$，$n=4$，$\bar{x}=25$。无序对差之和：

$$
|90-5|+|90-3|+|90-2|+|5-3|+|5-2|+|3-2|=85+87+88+2+3+1=266
$$

有序对差之和为 $2\times266=532$，分母 $2\times4^2\times25=800$，$G=532/800=0.665$。Gini 对"少数大户"敏感，但对"地址聚类"同样敏感：交易所 omnibus 地址会把大量用户资产集中到一个地址，制造虚假的不平等。

**Nakamoto 系数**：按份额降序累加，达到阈值（1/3、1/2、2/3）所需的最少实体数。它回答"多少人合谋才能控制"，比 HHI 更直观。

### 3.5 地址聚类与标签

常用启发式：

| 启发式 | 信号 | 假阳性 |
|---|---|---|
| 共同存入地址 | 多个地址向同一交易所充值地址转账 | 交易所内部归集、做市商 |
| gas 资金来源 | 新地址由同一地址支付 gas |  faucet、空投分发、交易所提现 |
| 交易时序 | 多个地址在同一区块/同一模式交易 | 机器人、批量任务 |
| 合约交互图 | 地址共享稀有合约/路由 | 热门协议、公共基础设施 |
| 标签库 | ENS、推特、GitHub、审计报告 | 标签过期、同名 |
| UTXO 共同输入 | 比特币交易多输入属于同一实体 |  CoinJoin、托管 |

**原则**：聚类是**概率性的**，必须报告置信度与误判率；不要把"同一实体"当作事实，除非有链下证据。

### 3.6 数据偏差：女巫、刷量、幸存者

| 偏差 | 表现 | 检测 | 处理 |
|---|---|---|---|
| 女巫（Sybil） | 大量地址领空投后消失 | 资金图、行为相似度、设备指纹（链下） | 排除/降权、人格证明 |
| 刷量（wash trading） | 自买自卖、循环交易 | 资金闭环、同区块、相同金额、手续费贡献 | 过滤自融资地址、按净费用计 |
| 机器人 | 高频、规律、低价值 | 交易间隔、gas 价格、合约调用模式 | 单独分类，不计入"人类用户" |
| 幸存者偏差 | 只看当前存活协议 | 加入已死亡项目、退市数据 | 全样本/历史回溯 |
| MEV | 三明治、套利污染成交量 | 交易排序、DEX 价差、失败交易 | 剔除或单列 |
| 激励扭曲 | 空投前刷量、TVL 挖矿 | 事件研究、断点回归 | 对照组合、清洗期 |

**案例：Blur（2023）**。Blur 的空投与 bidding 激励让用户频繁挂单/撤单、刷交易量，NFT 市场成交量在短期内被显著抬高；剔除刷量后，真实收藏者需求远低于 headline volume。分析 NFT 市场时，应同时报告"总成交量"与"付费用户数/净手续费"。

## 4. 实证方法

### 4.1 事件研究

对每个事件日 $t$，计算异常收益：

$$
AR_{i,t}=R_{i,t}-E[R_{i,t}],\qquad CAR_i=\sum_{t=t_1}^{t_2}AR_{i,t}
$$

**手算示例**：某代币三日收益率 $[3\%,-1\%,1\%]$，市场基准 $[1\%,0\%,-2\%]$，则 $AR=[2\%,-1\%,3\%]$，$CAR=4\%$。事件研究的关键是**基准模型**（市场模型、行业指数、匹配对照组）与**事件窗口**（不能把事件后的其他冲击混入）。

### 4.2 双重差分（DID）

|  | 处理前 | 处理后 | 差值 |
|---|---:|---:|---:|
| 处理组 | 100 | 130 | +30 |
| 对照组 | 90 | 105 | +15 |
| DID |  |  | **+15** |

DID 估计量：

$$
\hat{\beta}_{DID}=(\bar{Y}_{T,post}-\bar{Y}_{T,pre})-(\bar{Y}_{C,post}-\bar{Y}_{C,pre})
$$

核心假设是**平行趋势**：没有处理时，处理组与对照组的趋势相同。空投研究常用"未达门槛但特征相近"的地址作对照，或用在门槛附近的断点回归（RD）。需要注意：处理组可能提前改变行为（anticipation）、对照组被溢出效应污染（SUTVA 违背）、地址聚类错误导致分组错误。

### 4.3 面板回归

$$
Y_{it}=\alpha_i+\lambda_t+\beta D_{it}+\varepsilon_{it}
$$

- $\alpha_i$：个体固定效应，吸收地址/协议的长期差异；
- $\lambda_t$：时间固定效应，吸收市场整体行情；
- $D_{it}$：处理指示变量；
- 标准误按实体/时间聚类，处理序列相关。

常见陷阱：把"地址"当"用户"、把"交易数"当"参与度"、用未来信息定义处理组、忽略协议升级/空投规则变化、p-hacking。稳健性检验：安慰剂检验、替换指标、改变窗口、leave-one-out、预注册。

## 5. 代码与实现

### 5.1 SQL：DEX 日成交量与费用

```sql
-- 以 Dune 风格的事实表为例；表名因数据源而异
select
  date_trunc('day', block_time) as day,
  pool,
  sum(amount_usd) as volume_usd,
  sum(amount_usd) * 0.003 as fees_usd,
  count(distinct taker) as traders
from dex.trades
where block_time >= now() - interval '30' day
  and project = 'uniswap'
group by 1, 2
order by 1 desc;
```

真实分析还要：过滤失败交易、去重、统一代币精度、处理多链、按池分组、标注刷量地址。

### 5.2 JS：索引器的核心逻辑

```js
// 事件主键 = (txHash, logIndex)，保证幂等
const key = `${ev.txHash}:${ev.logIndex}`;
if (seen.has(key)) continue;
seen.add(key);

// 同一高度不同哈希 = reorg：回滚该高度及以上
if (block.number <= lastApplied && applied.get(block.number)?.hash !== block.hash) {
  rows = rows.filter(r => r.blockNumber < block.number);
  for (const n of [...applied.keys()]) if (n >= block.number) applied.delete(n);
  lastApplied = block.number - 1;
}
```

这正是 Lab 17.2 的骨架。生产环境还要加：确认数、最终性、RPC 重试、schema 版本、监控与告警。

### 5.3 指标函数

```js
const hhi = (shares) => shares.reduce((s, x) => s + (x * 100) ** 2, 0);
const gini = (xs) => {
  const n = xs.length, mean = xs.reduce((a, b) => a + b, 0) / n;
  let d = 0;
  for (let i = 0; i < n; i++) for (let j = 0; j < n; j++) d += Math.abs(xs[i] - xs[j]);
  return d / (2 * n * n * mean);
};
```

Lab 17.1 用它们计算原始地址、实体聚类、剔除交易所三种视图。

## 6. 案例

- **Uniswap UNI 空投（2020-09）**：向约 25 万个历史地址分发 1.5 亿 UNI（占总供应 15%）。空投后出现大量"领完即走"地址，短期交易量与治理参与集中在少数地址；分析留存时必须区分"领空投"与"真实使用"。
- **Blur 刷量（2023）**： bidding 激励与空投预期让成交量虚高；剔除自融资/循环交易后，真实需求低得多。headline volume 不能直接当作"市场规模"。
- **Lido + EigenLayer 再质押（2024）**：同一份 ETH 在 Lido TVL、EigenLayer TVL、LRT 协议 TVL 中重复出现；不同数据源的"总 TVL"不可直接相加，必须看净资本与负债。
- **Curve Vyper 漏洞（2023-07）**：事件研究可以观察池子资金流、LP 撤离、稳定币脱锚的传播；但要注意把"漏洞事件"与"市场整体下跌"分开，需要对照组。

## 7. CS / 工程视角

| 本章概念 | 已有计算机知识 | 对应关系 |
|---|---|---|
| 索引器 | ETL / 流处理 | 原始日志 → 解码 → 事实表 → 指标 |
| 事件主键 | 数据库唯一键 | `(txHash, logIndex)` 保证幂等 |
| reorg 回滚 | 事务回滚 / 事件溯源 | 按区块高度回滚，重放新块 |
| 抽象表 | 星型模型 / 数据仓库 | 事实表 + 维度表 + 指标表 |
| 指标口径 | 数据契约 / schema | 定义、版本、血缘、可复现 |
| 地址聚类 | 图算法 / 实体解析 | 资金图、行为相似度、标签 |
| 事件研究 | 因果推断 | 处理效应、对照组、平行趋势 |
| 留存分析 |  Cohort analysis | 按首次使用分组，跟踪后续行为 |

**工程启示**：数据分析的瓶颈通常不是 SQL，而是**数据质量与口径**。一个可复现的看板应包含：数据源、抓取时间、解码版本、过滤规则、指标定义、已知偏差。没有这些，数字只是"看起来精确"。

## 8. 常见误区

1. **"TVL 就是净流入。"** 事实：TVL 是锁仓资产按价格加总，包含重复计算与价格波动；净流入要看链上资金流与负债。
2. **"活跃地址 = 用户数。"** 事实：地址可能是机器人、交易所 omnibus、空投农民；一个用户也可能有多个地址。
3. **"交易量高 = 需求高。"** 事实：刷量、激励、MEV 都会抬高成交量；应同时看净手续费、付费用户、留存。
4. **"HHI 高 = 一定会被攻击。"** 事实：HHI 是集中度描述，不是攻击可行性；还要看治理规则、时间锁、流动性、地址聚类。
5. **"事件研究 = 因果。"** 事实：事件研究只描述异常收益；因果需要对照组、平行趋势、排除混杂因素。
6. **"数据是客观的。"** 事实：口径、过滤、聚类、标签都包含判断；不披露方法的指标不可复现。
