## 1. 直觉：当铺、银行与资金池

假设 Alice 想借 1 万美元，但她在链上只有一个 ETH 钱包。**当铺**按金项链市价的七成放款，还不上就卖掉项链——这是超额抵押借贷；**银行**用工资流水和征信判断还款能力，违约走法院——DeFi 没有法院，也没有统一征信；**资金池**让很多存款人把钱放进同一池子，利率由池子的“忙闲程度”决定（Aave、Compound）；**点对点撮合**把存款直接匹配给借款人（Morpho）。本章的核心问题是：**在没有身份、没有法院、价格剧烈波动的环境里，如何让借钱既高效又不把存款人炸掉？**

## 2. 资金池 vs 点对点

### 2.1 资金池（pooled lending）

以 Aave、Compound 为代表：所有存款进入同一市场（例如 ETH 市场、USDC 市场），借款人按统一利率借款。

| 维度 | 资金池 | 点对点撮合 |
|---|---|---|
| 流动性 | 好：随时可借可还 | 取决于是否有匹配对手方 |
| 利率 | 由利用率统一决定 | 可由双方/撮合器定价 |
| 风险隔离 | 同一市场内共享风险 | 每个市场/每笔贷款可隔离 |
| 资本效率 | 存款人资金被池子统一调配 | 匹配成功时更高，失败时闲置 |
| 治理复杂度 | 参数多、影响面大 | 市场创建更无许可，但碎片化 |
| 典型协议 | Aave v3、Compound v3 | Morpho Blue、Morpho Optimizer |

**Morpho 的关键设计**：Morpho Blue 允许任何人创建“孤立市场”——指定抵押品、贷款资产、LLTV（清算贷款价值比）和预言机，风险不传染；Morpho Optimizer 则在池子利率之上做点对点匹配，匹配不到时回落到池子。资金池的优势是**流动性聚合**（随借随还），代价是风险在同一市场内共享——一个参数错误或一次预言机操纵，可能让所有存款人一起承担坏账。后面的清算、坏账与风险参数，主要就是在管理这个代价。

## 3. 利率：利用率如何定价

### 3.1 利用率

设某市场总存款为 $S$（以计价资产计），总借款为 $B$。资金池里真正闲置的现金是 $S-B$。定义**利用率**：

$$
U=\frac{B}{S}=\frac{B}{B+\text{cash}}
$$

$U=0$ 时没人借钱，存款人几乎拿不到利息；$U\to1$ 时池子几乎没有流动性，新的提款都可能失败。所以利率必须在 $U$ 高时陡升：这既是对借款人的“拥堵定价”，也是对存款人的流动性风险补偿。

### 3.2 分段线性利率模型

最常见的**拐点模型（kink model）**：

$$
r_b(U)=
\begin{cases}
r_0+\dfrac{U}{U^*}s_1, & U\le U^*,\\[2ex]
r_0+s_1+\dfrac{U-U^*}{1-U^*}s_2, & U>U^*.
\end{cases}
$$

其中 $r_0$ 是基础利率，$U^*$ 是拐点（常见 80%–92%），$s_1$ 是拐点前的斜率，$s_2$ 是拐点后的斜率，通常 $s_2\gg s_1$。

**为什么需要拐点？** 如果利率对 $U$ 线性，$U=95\%$ 时利率可能仍然温和，借款人没有动力还款，存款人也没有动力追加存款，池子会被抽干。拐点之后陡升，相当于给“最后 10% 的流动性”标一个很高的价格。

### 3.3 存款利率

借款人支付的总利息是 $r_b\cdot B$。这些利息先由协议抽取**储备因子** $\rho$（reserve factor），剩下的按存款份额分给存款人。每 1 单位存款对应的毛利息是 $r_b\cdot U$，因此：

$$
r_s=r_b\cdot U\cdot(1-\rho).
$$

**推导**：总利息 $=r_bB$；可分配利息 $=r_bB(1-\rho)$；存款总额 $S$；所以 $r_s=r_bB(1-\rho)/S=r_bU(1-\rho)$。

注意 $r_s<r_b$ 有两个原因：只有被借出去的部分（$U$）产生利息；协议还要抽成（$\rho$）。存款利率不是“无风险利率”，它承担了智能合约、清算和坏账风险。

### 3.4 手算示例

取 $r_0=0$，$U^*=80\%$，$s_1=4\%$，$s_2=50\%$，$\rho=10\%$。

- $U=80\%$：$r_b=4\%$，$r_s=4\%\times0.8\times0.9=2.88\%$。
- $U=90\%$：$r_b=4\%+\frac{0.1}{0.2}\times50\%=29\%$，$r_s=29\%\times0.9\times0.9=23.49\%$。
- $U=95\%$：$r_b=4\%+\frac{0.15}{0.2}\times50\%=41.5\%$，$r_s=41.5\%\times0.95\times0.9=35.48\%$。

从 80% 到 90%，利用率只增加 10 个百分点，借款利率却从 4% 涨到 29%——这就是拐点的作用。

### 3.5 利息指数与复利

链上不可能每次交互才结算利息。协议维护**借款指数**（borrow index）$I(t)$，按秒复利：$I(t+\Delta t)=I(t)(1+r_b/s)^{s\Delta t}$，其中 $s=31{,}536{,}000$，债务 $D(t)=D_0 I(t)/I(0)$。例：$r_b=4\%$ 时有效年利率为 $(1+0.04/s)^s-1\approx e^{0.04}-1=4.081\%$，比单利高 8 个基点；$r_b=29\%$ 时约 $e^{0.29}-1=33.63\%$。利率越高，复利差异越大。

## 4. 健康因子、清算与坏账

### 4.1 LTV 与清算阈值不是一回事

**LTV（loan-to-value）** 决定你最多能借多少（LTV=75%，抵押 \$20,000 最多借 \$15,000）；**清算阈值 LT** 决定何时触发清算（LT=80%，债务/抵押品价值超过 80% 时可被清算）。两者之间的**缓冲**：LTV=75%、LT=80% 时，价格要跌约 $1-0.75/0.80=6.25\%$ 才触发清算。缓冲越大，清算越不频繁，但资本效率越低。

### 4.2 健康因子

对多抵押品、多债务的头寸：

$$
HF=\frac{\sum_i C_i P_i\,LT_i}{\sum_j D_j P_j}.
$$

分子是“风险调整后的抵押品价值”，分母是债务价值。$HF<1$ 时触发清算；$HF$ 越接近 1，缓冲越薄。

**手算示例**：抵押 10 ETH，ETH 价格 \$2,000，LT=80%，债务 \$12,000。

$$
HF=\frac{10\times2000\times0.8}{12000}=\frac{16000}{12000}=1.3333.
$$

令 $HF=1$，求清算价格：

$$
10\times P\times0.8=12000\Rightarrow P=\frac{12000}{8}=1500.
$$

即 ETH 从 \$2,000 跌到 \$1,500（-25%）时触发清算。

### 4.3 清算激励与 close factor

清算人不是志愿者：他们替借款人还债，换回**折价**的抵押品。设清算奖励为 $\beta$（例如 5%），清算人偿还 $R$ 的债务，可以拿走价值 $R(1+\beta)$ 的抵押品：

$$
\Delta C=\frac{R(1+\beta)}{P}.
$$

**close factor** 限制单次能还多少：Compound v2 常见 50%，Aave 在 $HF$ 很低时允许接近 100%。限制 close factor 的目的是防止一次清算把大额头寸全部打穿、造成价格冲击；代价是清算可能不够快。

继续上面的例子，ETH 跌到 \$1,400（-30%），$HF=0.9333<1$。假设 close factor=50%、$\beta=5\%$：

- 第一次最多偿还 $12{,}000\times50\%=6{,}000$；
- 拿走 $6{,}000\times1.05/1400=4.5$ ETH；
- 剩余抵押 $5.5$ ETH，剩余债务 $6{,}000$，新 $HF=5.5\times1400\times0.8/6000=1.0267$，清算停止。

清算人毛利 $=6{,}000\times5\%=300$（未扣 gas）。如果 gas 是 \$300，清算人恰好无利可图；如果 gas 更高，清算会停滞——这正是黑天鹅中坏账的来源之一。

### 4.4 荷兰式拍卖：Maker 的做法

固定折扣清算的问题是：市场瞬间崩盘时，固定的 5% 奖励可能不足以补偿清算人的风险，导致无人接盘。Maker 的抵押品拍卖采用**荷兰式拍卖**：起拍价 $P_0=P_m(1+\delta)$ 高于市场价（对清算人不利），再在 $T$ 时间内降到 $P_m(1-\delta')$，直到有人愿意买；清算人每单位利润约为 $P_m-P_{\text{auction}}$，扣除 gas 与成交风险。拍卖设计的关键是**速度与折扣的权衡**：起拍折扣太小、下降太慢，清算不及时，坏账扩大；折扣太大、下降太快，清算人拿走过多价值，存款人受损。

### 4.5 坏账：抵押品不够还债

当价格跳空或清算不及时，抵押品全部卖掉也不够还债，缺口就是**坏账**（bad debt），由存款人或协议金库承担。若清算人拿走 $(1+\beta)$ 倍对价，坏账为：

$$
\text{BadDebt}=\max\left(0,\;D-\frac{C\cdot P}{1+\beta}\right).
$$

**手算示例**：10 ETH、债务 \$12,000、$\beta=5\%$，ETH 跌到 \$1,100：

$$
\text{BadDebt}=12000-\frac{10\times1100}{1.05}=12000-10476.19=1523.81.
$$

注意：坏账在“抵押品市值 = 债务”之前就出现了。临界价格是

$$
P_{\text{bad}}=\frac{D(1+\beta)}{C}=\frac{12000\times1.05}{10}=1260.
$$

也就是说，ETH 跌到 \$1,260 时，抵押品市值还有 \$12,600（大于债务 \$12,000），但清算人要求 5% 的奖励，卖完只够还 \$12,000，缺口开始出现。这是很多人忽略的细节：**清算奖励本身就是一种“坏账触发器”**。

### 4.6 压力测试：30% 下跌够不够？

用上面的头寸：ETH 从 \$2,000 跌到 \$1,400，$HF=0.9333$，第一次清算后 $HF=1.0267$，没有坏账。但如果有 500 个头寸、初始 LTV 分布在 30%–78%，30% 下跌会把当前 LTV 推到初始值的 $1/0.7$ 倍；当当前 LTV 超过 $1/(1+\beta)\approx95.2\%$ 时，坏账开始出现，对应初始 LTV 超过 $0.7/(1+\beta)\approx66.7\%$。Lab 10.1 的固定种子模拟给出：500 个头寸、总债务约 \$5.52M，其中 119 个头寸产生约 \$127k 坏账，坏账率 2.31%。

这说明：**同一个价格冲击，对不同 LTV 的头寸影响完全不同**；风险参数（尤其是 LTV 上限）决定了尾部坏账的规模。

## 5. 闪电贷

### 5.1 原子性

闪电贷（flash loan）允许你在**同一笔交易**内借出资产、使用、并在交易结束前归还本金加费用。如果归还失败，整个交易回滚（revert），就像什么都没发生。

```solidity
// 简化伪代码：Aave 风格的闪电贷
function flashLoan(address receiver, uint256 amount) external {
    uint256 before = token.balanceOf(address(this));
    token.transfer(receiver, amount);
    IFlashLoanReceiver(receiver).executeOperation(amount, fee);
    require(token.balanceOf(address(this)) >= before + fee, "not repaid");
    // 若 require 失败，EVM 回滚所有状态变更
}
```

关键点：**不需要抵押**，因为不存在“跨交易”的信用风险；风险被替换成了“原子性风险”——还不上就当作没借过。费用通常很低（Aave 历史上 0.05%–0.09%，Balancer 部分资产为 0）。

### 5.2 合法用途

**套利**（借资金同时完成 DEX 间买卖）、**抵押品置换**（借新还旧，换更便宜的抵押品）、**自清算**（自己清算自己，避免奖励被第三方拿走）、**治理投票**（临时借入治理代币，是否合法取决于治理规则）。

### 5.3 攻击面：闪电贷不是漏洞

闪电贷本身只是“放大了攻击者的资本”，真正的漏洞通常是：**现货价格预言机**（用闪电贷打高 AMM 价格，按虚高价借款）、**可操纵的抵押品估值**（donation attack 改变池子储备或份额价格）、**重入与状态不一致**（回调期间状态未更新）。Euler Finance 2023 年 3 月约 \$197M 的损失，就是攻击者利用捐赠/清算逻辑缺陷（并非单纯闪电贷）造成的；2020 年 bZx 则展示了闪电贷 + 价格操纵的组合。Lab 10.2 会把“闪电贷 → 操纵 AMM 现货价 → 超额借款 → 坏账”完整算一遍。**防御**：去中心化预言机（Chainlink、Pyth）、TWAP、多源中位数、借款上限、价格偏差熔断、延迟清算——没有单一措施能完全消除风险。

## 6. 无抵押信用与信息不对称

### 6.1 为什么 DeFi 几乎都是超额抵押

无抵押借贷面临两类经典问题：**逆向选择**——最想借钱的人往往最可能还不上，好人被坏人的利率挤出市场（Akerlof 的“柠檬市场”）；**道德风险**——借到钱后，借款人可能投向更高风险的项目，甚至直接不还。传统金融用征信、工资流水、抵押登记、法院执行来缓解；DeFi 没有身份与法律执行，所以早期几乎只能做超额抵押。超额抵押的本质是：**用可清算的资产替代法律追索权**。

### 6.2 信用风险定价

对无抵押贷款，最低利率至少要覆盖：

$$
\text{Required Rate}=\text{funding}+\text{opex}+\underbrace{PD\times LGD}_{\text{expected loss per unit EAD}}+\text{capital charge}.
$$

其中 $PD$ 是违约概率，$LGD$ 是违约损失率，$EAD$ 是违约风险暴露。期望损失 $EL=PD\times LGD\times EAD$。

**手算示例**：$PD=4\%$，$LGD=55\%$，$EAD=\$2M$：

$$
EL=0.04\times0.55\times2{,}000{,}000=\$44{,}000,
$$

即需要 2.2% 的信用利差。若资金成本 3%、运营成本 1%，最低利率约 $3\%+1\%+2.2\%=6.2\%$。如果实际只收 4%，每笔贷款的期望收益为负。

### 6.3 链上尝试

**Goldfinch / Centrifuge / Maple / TrueFi** 把 RWA 或机构借款搬到链上，靠链下承销、法律合同与 SPV 结构；Goldfinch 2023 年的借款人违约/重组说明“链下信用”仍然是信用。**Aave credit delegation** 让存款人授权借款人使用自己的信用额度，风险由授权人承担。**声誉与链上历史**用还款记录、收入流、社交图谱评分，但地址可抛弃、Sybil 成本低，可移植性有限。**隔离市场与机构池**则把无抵押/低抵押贷款放进独立池子，不让风险传染给普通存款人。

> 核心结论：无抵押信用的瓶颈不是“链上能不能记账”，而是“违约后能不能执行”。在没有法律执行的环境里，超额抵押、隔离市场、链下承销是三种不同的替代方案。

## 7. 风险参数治理

借贷协议的参数直接决定存款人的尾部风险。常见参数：

| 参数 | 作用 | 调高的后果 | 调低的后果 |
|---|---|---|---|
| LTV | 最大借款比例 | 资本效率高，清算缓冲薄 | 安全但需求下降 |
| 清算阈值 LT | 触发清算的债务/抵押比 | 更早清算，坏账少，但清算频繁 | 缓冲大，但可能来不及 |
| 清算奖励 $\beta$ | 激励清算人 | 清算积极，但坏账阈值提前 | 激励不足，清算停滞 |
| 储备因子 $\rho$ | 协议收入 | 存款利率下降 | 协议收入不足 |
| 供应上限 | 限制某资产暴露 | 风险集中 | 业务受限 |
| 预言机 | 价格来源 | 低延迟但可操纵 | 稳健但滞后 |

治理的三个难题：**参数滞后于市场**（投票需要时间，黑天鹅不等人）；**治理攻击**（借入治理代币，通过恶意参数掏空池子）；**风险外包**（交给 Gauntlet、Chaos Labs 等专业风险管理方，效率提高但引入中心化与激励冲突）。

实践中的组合：**保守的 LTV + 隔离市场 + 供应上限 + 多源预言机 + 紧急暂停**。没有“最优参数”，只有在资本效率与尾部风险之间的取舍。

## 8. 代码 / 实现

下面是一个极简的借贷池核心（Solidity 风格伪代码），把利率、指数、健康因子串起来：

```solidity
contract MiniLendingPool {
    uint256 public totalCash;      // 池中闲置现金
    uint256 public totalBorrows;   // 总债务（含利息）
    uint256 public borrowIndex = 1e27; // Ray，按秒复利

    function utilization() public view returns (uint256) {
        uint256 total = totalCash + totalBorrows;
        return total == 0 ? 0 : totalBorrows * 1e27 / total;
    }

    function borrowRate() public view returns (uint256) {
        uint256 u = utilization();
        if (u <= 0.8e27) return u * 0.04e27 / 0.8e27;
        return 0.04e27 + (u - 0.8e27) * 0.50e27 / 0.2e27;
    }

    function accrue() public {
        uint256 ratePerSecond = borrowRate() / 365 days;
        borrowIndex = borrowIndex * (1e27 + ratePerSecond) / 1e27;
    }

    function healthFactor(address user) public view returns (uint256) {
        return collateralValue(user) * liquidationThreshold(user) / debtValue(user);
    }
}
```

工程要点：

- **定点数**：Solidity 没有浮点，常用 `Wad`（1e18）或 `Ray`（1e27）；乘除顺序决定舍入误差，舍入应偏向协议安全；
- **指数结算**：每次交互先 `accrue()`，用指数把“历史利息”一次性滚动到当前；
- **不变量**：`cash + borrows - reserves == totalSupply`（以同一计价单位），任何函数都不能破坏它；
- **预言机**：价格必须带时间戳与置信区间，拒绝过期价格；
- **重入**：清算、闪电贷回调、抵押品转移都要遵循 checks-effects-interactions 或重入锁。

Lab 10.1 用 JS 复现了利率曲线与清算账本；Lab 10.2 用 JS 演示闪电贷回滚与预言机操纵。两段代码都不依赖链，便于先算清楚再上链。

## 9. 案例

### 9.1 MakerDAO 的“黑色星期四”（2020-03-12）

ETH 单日暴跌约 40%，链上拥堵、gas 飙升。Maker 的拍卖依赖 keeper 机器人，但很多机器人在拥堵中无法及时出价；出现了大量**以 0 DAI 成交**的抵押品拍卖，约 6.3 万 ETH 被清算，协议产生数百万美元坏账，随后通过增发 MKR 拍卖弥补。

教训：清算激励必须覆盖**极端 gas** 与**链上拥堵**；荷兰式拍卖的启动参数、时长、keeper 多样性都影响结果；预言机延迟与市场深度不足会让“有抵押”变成“资不抵债”。

### 9.2 Euler Finance（2023-03）与 Aave CRV 事件（2022-11）

Euler 的攻击者利用健康检查/清算逻辑缺陷（结合闪电贷与捐赠），造成约 \$197M 损失，后续大部分资金被追回——**闪电贷只是资本放大器，真正的 bug 在协议会计逻辑**。Aave 的 CRV 空头事件则暴露了“低流动性抵押品 + 高借款上限”的风险：抵押品账面市值够，但市场深度不足以承接清算。

## 10. CS / 工程视角

| 计算机概念 | 在借贷协议中的对应 |
|---|---|
| 状态机 | 存款、债务、抵押品、健康因子是状态；借款/还款/清算是状态转换 |
| 数据库事务 | 闪电贷是“带自动回滚的事务”：任何一步失败，整个事务回滚 |
| 复式记账 / 不变量 | `assets = liabilities + reserves`；每次状态转换后必须成立 |
| 定点数运算 | Wad/Ray；舍入方向决定谁承担微小误差 |
| 事件日志与守护进程 | `Borrow`/`Repay`/`Liquidation` 事件驱动清算机器人 |
| 资源计量 | gas 是清算的固定成本；gas 上升会改变清算激励 |
| 权限与治理 | 参数管理员、暂停 guardian、时间锁、多签 |

一个重要的工程视角：**借贷协议的风险不是一个数字，而是一条链**——预言机 → 价格 → 健康因子 → 清算机器人 → DEX 流动性 → 坏账。任何一个环节延迟或失灵，都会传导到存款人。压力测试应该端到端地做，而不是只看当前 HF。

## 11. 常见误区

1. **“HF < 1 就一定能收回全部债务。”** 清算奖励、价格跳空、市场深度不足、gas 拥堵都可能让抵押品卖不出足够价值，产生坏账。
2. **“LTV 就是清算阈值。”** LTV 决定最大借款额，LT 决定清算触发点；两者之间的缓冲是风险设计的一部分。
3. **“闪电贷是漏洞。”** 闪电贷是原子性工具；漏洞通常在于预言机、价格操纵、重入或会计逻辑。
4. **“存款利率 = 借款利率。”** $r_s=r_bU(1-\rho)$，只有被借出的部分生息，协议还要抽成。
5. **“超额抵押没有信用风险。”** 超额抵押把信用风险换成了市场风险、流动性风险、预言机风险和清算风险。
6. **“TVL 越大越安全。”** TVL 可能包含循环杠杆（同一资产反复抵押），且风险集中在少数参数与预言机上。
