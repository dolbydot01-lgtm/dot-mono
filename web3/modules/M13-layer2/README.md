# M13 · Layer 2 与模块化区块链

> 一句话：L2 不是"更快的以太坊"，而是把执行外包出去、把数据和结算拉回 L1 的一整套工程与经济学妥协。

## 学习目标

完成本章后，你应该能够：

1. 用"执行、结算、共识、数据可用性"四个职能拆解一条链，并解释 Rollup、Validium、侧链、分片分别外包了哪一层。
2. 说清 Optimistic Rollup 与 ZK Rollup 的信任来源、最终性时间和成本结构，而不是只背"7 天"和"零知识"。
3. 用 L2BEAT 的 Stage 0/1/2 框架判断一个 L2 的真实成熟度，并指出"有欺诈证明"与"欺诈证明无需许可"的区别。
4. 区分 zkEVM Type 1–4 的兼容性取舍，理解"EVM 等价"为什么在证明系统里代价很高。
5. 解释 EIP-4844 blob、DAS、PeerDAS 与外部 DA 的关系，以及"数据可用"为何是 Rollup 的安全前提。
6. 用公式和手算拆解 L2 的费用：用户费用、L1 数据成本、执行成本、利润与盈亏平衡点。
7. 识别排序器中心化、共享排序、based rollup 各自的风险与取舍。

## 1. 直觉：把"堵车"拆成四种工作

想象一条繁忙的高速公路。扩容有三种朴素思路：

- 把路修宽：提高 L1 的 gas limit 或分片。问题是全世界的验证者都要承担更高的带宽与存储成本，去中心化会被侵蚀。
- 在旁边修辅路：把交易拿到链下执行，只在 L1 上登记结果。这就是 Rollup。
- 把货物拆箱、拼车：把多笔交易压缩成一个批次，摊薄固定成本。这是 Rollup 的批处理层。

关键洞察是：**执行可以外包，但"最终发生了什么"必须可验证，且任何人都要能拿到证明所需的数据。** 于是 Rollup 把工作拆成四块：

1. **执行**：在 L2 上跑 EVM，产生新状态根。
2. **结算**：把状态根和批次数据提交到 L1，由 L1 合约裁决。
3. **数据可用性（DA）**：确保任何人都能下载批次数据，独立重放并发现错误。
4. **共识/排序**：决定交易顺序。绝大多数 L2 目前由单一排序器完成。

"模块化区块链"就是把这几块做成可替换的组件：执行层用 OP Stack / zkEVM，DA 层用以太坊 blob 或 Celestia，结算层用以太坊，排序层用共享排序市场。模块化不是目的，而是为了让每个组件独立竞争、独立定价。

### 1.1 不可能三角，准确的说法

"去中心化、安全、可扩展"三者不可兼得，是一个有用的简化，但容易误导。更准确的说法是：

- 在**单层**链上，提高吞吐会增加普通节点验证全链的成本，从而削弱去中心化。
- Rollup 并没有"消除"三角，而是把执行挪到链下，让 L1 只保留**验证**与**数据**职能。代价是引入了新的信任假设：排序器、证明系统、桥、DA 层。
- 所以正确的问题不是"L2 是否解决了三角"，而是"**哪一项被外包了，外包引入了什么新的失败模式**"。

分片与 Rollup 是两条不同的路：

| 路线 | 扩容方式 | 安全性来源 | 主要代价 |
|---|---|---|---|
| 分片 | L1 把状态/执行切成多片并行 | L1 共识 + 数据可用性采样 | 跨片通信复杂、协议改动大、开发周期长 |
| Rollup | 执行移到 L2，L1 做结算与 DA | L1 合约 + 证明/挑战 + DA | 排序器中心化、桥风险、证明成本 |
| 侧链 | 独立共识、独立验证者 | 自己的验证者集合 | 不继承 L1 安全，桥是单点 |
| Validium | 执行在链下，数据放链下 DA | 证明 + 外部 DA 委员会 | DA 委员会串谋/宕机时资金可被冻结 |

以太坊的实际路线是"以 Rollup 为中心"：L1 提供结算与 DA，分片技术（Danksharding）主要服务于 blob 数据扩容，而不是把执行切碎。

## 2. 形式化与机制

### 2.1 Rollup 的状态转移

设 L2 状态为 `S`，批次内交易序列为 `Txs`，执行函数为 `f`。排序器计算：

```
S' = f(S, Txs)
```

然后把 `(S, S', commitment(Txs))` 提交到 L1。L1 合约必须能回答两个问题：

1. **有效性**：`S'` 是否真的是 `f(S, Txs)` 的结果？
2. **数据可用性**：任何人是否能拿到 `Txs`，从而独立重算 `S'`？

Optimistic Rollup 对问题 1 采用"默认正确 + 欺诈证明"；ZK Rollup 采用"提交时附有效性证明"。两者都必须解决问 2，否则验证者无法重放，欺诈证明或证明生成都成了无源之水。

### 2.2 Optimistic vs ZK

| 维度 | Optimistic Rollup | ZK Rollup |
|---|---|---|
| 有效性来源 | 至少一个诚实观察者在挑战期内提交欺诈证明 | 密码学证明（SNARK/STARK） |
| 提款最终性 | 挑战期结束（常见 7 天） | 证明上链 + L1 最终性（分钟到小时） |
| L1 成本 | 批次数据 + 少量挑战/结算开销 | 批次数据 + 证明验证 gas + 证明生成成本 |
| 计算开销 | 链下执行，L1 只裁决争议 | 链下执行 + 证明生成（可能很重） |
| 主要风险 | 观察者缺席、审查、升级多签 | 证明系统 bug、可信设置、电路约束遗漏 |
| 资本效率 | 跨链桥需垫付 7 天流动性 | 资本占用低，适合支付/DeFi |

"7 天"不是物理定律。它是**安全窗口**与**资本成本**之间的社会选择：窗口越长，观察者越有时间发现并提交欺诈证明；窗口越短，用户体验越好，但攻击者重组链或审查证据的窗口也更紧。Arbitrum 的实际挑战期约为 6.4 天，OP Stack 常见配置为 7 天。

一个常见误解是"OP 的交易 7 天后才确认"。更准确地说：**L2 上的交易几秒内就被排序器接受，但把它安全地提回 L1 需要等挑战期。** 在 L2 内部转账、在 L2 上使用 DeFi，不需要等 7 天。

### 2.3 欺诈证明与 Stage 0/1/2

欺诈证明的核心不是"有人喊一声"，而是一个可交互的争议协议：挑战者指出某个中间状态错误，双方二分定位到具体指令，L1 合约只裁决这一步。这样 L1 不需要重放整个批次。

但"有欺诈证明合约"不等于"安全"：

- 证明提交是否**无需许可**？如果只有白名单提交者，白名单失效时无人能挑战。
- 升级是否由**多签即时执行**？如果是，多签可以绕过一切证明。
- 挑战期是否足够长，观察者是否真有动机监控？
- 排序器是否可以审查挑战交易？

L2BEAT 用 Stage 0/1/2 粗略刻画这些维度：

- **Stage 0（full training wheels）**：有证明系统或欺诈证明，但升级由多签控制，安全委员会可快速干预。
- **Stage 1（limited training wheels）**：证明系统实际运行且无需许可参与；升级有延迟；安全委员会有外部成员与较高阈值。
- **Stage 2（no training wheels）**：证明系统无需许可且覆盖全部状态；链上治理有长延迟；安全委员会只能在极窄条件下干预。

截至 2026 年，大多数生产 L2 仍在 Stage 0 或 Stage 1；Stage 2 要求"任何用户都能独立退出、任何升级都不能绕过证明"，工程门槛很高。读 L2BEAT 时不要只看 TVL，要看"谁能升级合约、谁能提交证明、数据存在哪"。

### 2.4 zkEVM 的四种类型

ZK Rollup 要给 EVM 执行生成证明。兼容性越强，电路越复杂、证明越慢：

| 类型 | 含义 | 优点 | 代价 |
|---|---|---|---|
| Type 1 | 与以太坊完全等价（包括共识层细节） | 直接复用工具链与合约 | 证明成本最高 |
| Type 2 | 完全 EVM 等价，但不等价于 L1 共识 | 兼容绝大多数合约 | 仍较重 |
| Type 2.5 | EVM 等价，但调整 gas 计量/少量系统合约 | 显著降低证明成本 | 极少数合约受影响 |
| Type 3 | 几乎 EVM 等价，缺失少数操作码/预编译 | 更容易优化 | 部分合约需改写 |
| Type 4 | 只兼容高级语言（Solidity/Vyper） | 电路最简单、证明最快 | 字节码层面不兼容，工具链受限 |

截至 2026 年，主流 zkEVM 多在 Type 2–Type 3 之间；Type 4 更接近"用 zkVM 跑 Solidity"，而不是"给 EVM 做证明"。选型时要问：我的合约是否依赖特定预编译、gas 语义、`blockhash` 或账户抽象行为？

### 2.5 数据可用性：从 calldata 到 blob 到 DAS

Rollup 必须让所有人拿到批次数据。演进路径：

1. **calldata**：早期 Rollup 把压缩后的批次写进 L1 calldata。永久存储，但按 calldata gas 计价，贵。
2. **EIP-4844 blob**（Dencun，2024-03）：每个 blob 有 4096 个域元素，每个元素 32 字节但只有 31 字节可用，因此容量为 `4096 × 31 = 126,976` 字节；blob gas 为 131,072/blob。blob 有独立的费用市场，且约 18 天后被修剪，不进入永久状态。
3. **DAS（数据可用性采样）**：轻节点随机下载若干数据块，以概率保证整块数据可用。全节点不再需要下载全部数据。
4. **PeerDAS（EIP-7594，Fusaka，2025-12）**：把 blob 数据切成列（column），验证者只 custody 部分列，通过抽样与纠删码保证可用性。它让 blob 数量可以继续提高，而不要求每个节点下载全部数据。
5. **外部 DA**：Celestia、EigenDA、Avail 等把数据可用性外包给独立网络。成本可能更低，但引入了新的信任假设：DA 层自己的验证者集合、桥、以及"数据确实被保留"的经济保证。

费用市场方面，blob 参数在 2025–2026 年连续上调：Pectra（2025-05）把 target/max 从 3/6 提高到 6/9；Fusaka 后的 BPO1（2025-12）提高到 10/15，BPO2（2026-01）提高到 14/21。参数会继续通过 BPO 分叉调整，读文档时要标注日期。

一个常见误区："blob 便宜，所以 L2 一定便宜。" 实际上 blob 只是数据成本的一部分；L1 提交交易的固定 gas、证明验证 gas、排序器运营、桥的流动性成本都要算进去。下一节的手算会看到，在 blob 费用很低时，固定提交成本才是大头。

### 2.6 排序器：最被低估的中心化点

排序器决定交易顺序，因而拥有事实上的**审查权、抢跑权与停机权**。目前多数 L2 的排序器由单一公司运行，只是承诺"以后去中心化"。

三种改进路线：

- **共享排序（shared sequencing）**：多个 Rollup 把排序需求卖给一个去中心化排序市场，排序者质押并受罚。它试图让跨 Rollup 的原子交易成为可能，但增加了跨域 MEV 与治理复杂度。
- **Based rollup**：把排序权交还给 L1 提议者（proposer）。L1 的提议者按自己的规则排序 L2 交易，L2 不再有自己的排序器。优点是继承 L1 的活性与抗审查；缺点是出块节奏受 L1 slot 限制，预确认需要 proposer 的额外承诺。
- **强制包含 / escape hatch**：允许用户绕过排序器，直接把交易提交到 L1 合约，强制 L2 在若干区块内包含。它保底抗审查，但延迟高、成本高。

评估一个 L2 时，除了 TPS 和费用，至少要问：排序器是谁？停机时用户能否强制退出？排序器能否延迟特定交易？跨链桥的验证者集合与 L2 排序器是否重叠？

### 2.7 L2 的经济学：收入不等于利润

课程采用的口径：

```
L2 收入 = 用户支付的费用 − L1 数据成本
L2 利润 = L2 收入 − 排序器/证明/运营/激励成本
```

其中 L1 数据成本包括：

```
L1 数据成本 = blob 成本 + 提交批次的 calldata/验证 gas
blob 成本  = blob 数量 × 131,072 blob gas × blob base fee(wei)
```

注意 blob base fee 的单位是"wei per blob gas"，不是"wei per blob"。把两者混为一谈会差 131,072 倍。

#### 手算示例：一个批次的费用拆分

参数（教学示例，非当前主网价格）：

- 每批 2,000 笔交易，原始 120 B/笔，压缩比 4:1，压缩后 30 B/笔。
- 批次数据量 `2,000 × 30 = 60,000 B`。
- blob 容量 126,976 B，所以只需 **1 个 blob**，利用率 `60,000 / 126,976 = 47.253%`。
- blob base fee = 12 wei/blob gas；L1 gas price = 20 gwei；ETH = $3,000。
- 每批 L1 提交/验证固定开销 = 60,000 gas。

计算：

```
blob 成本 = 1 × 131,072 × 12 = 1,572,864 wei
          = 1.572864e-12 ETH ≈ $4.72e-9
提交成本 = 60,000 × 20 gwei = 1,200,000 gwei = 0.0012 ETH = $3.60
L1 数据成本合计 ≈ 0.00120000000157 ETH ≈ $3.60
每笔分摊 = $3.60 / 2,000 = $0.0018
```

若每笔用户费用 $0.01：

```
用户费用总额 = 2,000 × $0.01 = $20.00
L2 收入 = $20.00 − $3.60 = $16.40
L2 执行成本 = 50,000 L2 gas × 0.001 gwei × $3,000 ≈ $0.00015/笔
            = $0.30/批
L2 利润 = $16.40 − $0.30 = $16.10，即 $0.00805/笔
```

这个例子说明两件事：

1. **blob 费用在低位时几乎可以忽略**，固定提交 gas 才是主要 L1 成本。
2. **利润对 blob 价格高度敏感**。令利润为零，可解出 blob base fee 的盈亏平衡点约为 `40,944,417,318 wei/blob gas`；超过这个价位，数据成本开始吞噬全部利润。计算过程见 Lab 13.1。

#### 第二个手算：挑战期的资本成本

提款 $10,000，资本机会成本 8%/年，OP 挑战期 7 天：

```
资本成本 = 10,000 × 0.08 × 7/365 = $15.34
快速桥收费 0.1% = $10.00
对用户：花 $10 买"立刻到账"，比等 7 天占用 $15.34 更划算
对做市方：盈亏平衡费率 = 0.08 × 7/365 = 0.153%
```

如果每天有 $2,000,000 提款、挑战期 7 天，做市方需常备 `$14,000,000` 流动性，年化机会成本 `$1,120,000`，相当于年提款量 `$730,000,000` 的 0.153%。这正是快速桥的商业模式：**把等待打包成金融产品**。

## 4. 案例

### 4.1 Arbitrum 与 OP Stack

Arbitrum（Nitro）和 OP Stack（Optimism、Base）都采用 Optimistic Rollup。它们的差异主要在欺诈证明的交互协议、批次压缩格式、排序器实现与治理结构。Base 由 Coinbase 运营排序器，继承了 OP Stack 的代码但有自己的中心化信任假设；读它的文档时要区分"代码开源"与"排序器去中心化"。

### 4.2 zkSync Era、Starknet、Scroll、Linea

这些 zkEVM/zkVM 路线在证明系统（Groth16/PLONK/STARK/FRI）、EVM 兼容级别、证明生成硬件上各不相同。共同点是：证明生成是重计算，验证在 L1 上很便宜；因此**批次越大、聚合越好，单位成本越低**。但证明系统越复杂，电路约束遗漏与实现 bug 的风险越高。

### 4.3 Dencun 之后的费用变化

EIP-4844 把 Rollup 的数据成本从 calldata 迁移到 blob，blob 有独立且通常更低的费用市场。2024 年 Dencun 后，主流 L2 的费用显著下降；2025 年 Pectra 与 2025–2026 年的 BPO 分叉继续提高 blob 容量。但费用下降不等于利润下降：竞争会把节省的成本让给用户，L2 的长期利润取决于排序权、MEV、生态锁定与差异化服务。

### 4.4 跨链桥与 L2 提款

L2 的官方桥通常要等挑战期（OP）或证明（ZK）。第三方快速桥通过垫付流动性缩短等待，代价是引入额外的信任假设：托管方、验证者集合、流动性枯竭风险。历史上最大的几起桥被盗事件（Ronin、Wormhole、Nomad）都说明：**桥的安全等于其最弱的那一个信任假设**，而不是其 TVL 或验证者数量。

## 5. CS/工程视角

把 L2 当成一个分布式系统，会看到几个经典问题：

- **批处理与压缩**：交易如何编码、哪些字段可以省略、状态差分如何压缩。压缩率每提高 1 倍，数据成本就减半。
- **证明流水线**：证明生成是批处理作业，可能耗时数分钟到数小时；需要任务队列、重试、聚合、证明缓存与失败回退。
- **排序器的活性与一致性**：单点排序器宕机时，L2 停止出块；需要逃生通道与强制包含。
- **DA 的对抗性**：DA 层如果隐瞒数据，L2 用户可能无法证明自己的资产状态；需要 DAS、纠删码、数据保留激励与外部 DA 的桥。
- **桥的最终性**：L1 重组、L2 重组、挑战期、证明延迟叠加，跨链消息的"最终"时间是一个偏序，不是单点。
- **可观测性**：批次大小、blob 利用率、证明时间、挑战提交、排序器延迟、桥的未匹配负债，都应该有仪表盘与告警。

一个实用的判断框架：**任何 L2 声称的"安全"都可以拆成"谁可以升级合约、谁可以提交证明、数据存在哪里、排序器能否审查、桥的验证者是谁"五个问题。** 五个答案都清楚，才算真正理解它。

## 6. 常见误区

1. **"L2 交易 7 天后才最终确认。"** 错。L2 内部几秒就接受；7 天是提回 L1 的挑战期。
2. **"有欺诈证明就是 Stage 1。"** 错。还要看证明提交是否无需许可、升级是否有延迟、安全委员会是否独立。
3. **"ZK Rollup 不需要信任。"** 错。它信任证明系统的可靠性、电路约束的完整性、可信设置（若使用）与实现正确性。
4. **"blob 便宜，所以 L2 利润一定高。"** 错。固定提交 gas、证明验证、运营与激励都要算；竞争还会把利润让给用户。
5. **"数据可用性只是存储问题。"** 错。它是安全前提：拿不到数据，就无法重放、无法发现欺诈、无法证明资产。
6. **"排序器去中心化就是多找几个节点。"** 错。需要明确的准入、质押、惩罚、抗串谋与跨域 MEV 规则；否则只是换了名字的中心化。
7. **"Type 4 zkEVM 更快，所以更好。"** 取决于目标：要无缝兼容现有合约，Type 2/3 更合适；要极致证明速度、可接受改写合约，Type 4 才有意义。
