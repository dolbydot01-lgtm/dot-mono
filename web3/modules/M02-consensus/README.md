## 1. 直觉：五个室友的公共账本

假设你和四个室友合租，要共同记一本"公共支出账"。规则必须处理两类问题：

- **有人掉线**：消息没收到、电脑坏了。这叫**崩溃故障（crash fault）**。
- **有人撒谎**：他可能给不同的人看不同的账本，甚至伪造记录。这叫**拜占庭故障（Byzantine fault）**。

同时，你们希望两件事：

- **安全性（safety）**：任何时刻，两个人不会都认为"第 7 笔是买咖啡"，而实际上是两笔不同的支出；
- **活性（liveness）**：只要大多数人还在线，新支出最终能被记进账本。

这两件事经常冲突。网络一乱，最安全的做法是"停下来，等大家重新同步"——这牺牲了活性；最灵敏的做法是"先记下来，之后再说"——这可能产生两条不同的账。

**为什么是 $1/3$？** 假设 5 个人中有 1 个骗子。你询问所有人，收到 5 份回复；骗子可以给不同的人发不同的版本。要保证你看到的"多数版本"里至少有一个诚实者，必须让任意两个多数集合的交集大于骗子人数。这个简单的交集计算，就是 BFT 里 $n \ge 3f+1$ 的来源。

区块链把这个"寝室账本"放大到全球：参与者互不相识、可以随时加入退出、还可能为了钱作恶。M2 要回答的就是：**在这样的环境下，用什么协议、什么激励，才能让一本账持续活下去？**

## 2. 形式化：模型、不可能性与 quorum

### 2.1 同步性、故障类型、安全性与活性

分布式共识的结论高度依赖**网络假设**：

| 模型 | 消息延迟 | 能得到的结论 |
|---|---|---|
| **同步（synchronous）** | 有已知上界 $\Delta$ | 可以容忍 $f < n/2$ 的崩溃故障；BFT 也可做 |
| **异步（asynchronous）** | 无上界，消息可能任意晚 | FLP：确定性协议无法同时保证安全性与活性 |
| **部分同步（partially synchronous）** | 一段时间后进入同步（GST） | 实用 BFT 的标准假设：GST 前保安全，GST 后保活性 |

**FLP 不可能性**（Fischer–Lynch–Paterson, 1985）：在完全异步网络中，即使只有一个进程可能**崩溃**，也不存在同时保证安全性与活性的**确定性**共识算法。

直觉证明：异步网络无法区分"某个节点已经崩溃"和"它的消息只是很慢"。协议在某个时刻必须决定是否继续等待；对手可以把关键消息延迟到任意晚，使协议永远无法安全地做出决定。工程上的绕法有四种：

1. **部分同步假设 + 超时**：PBFT、Tendermint、Raft 都这么做；
2. **随机化**：用随机币打破对称性，以概率 1 终止（如 Ben-Or）；
3. **故障检测器**：用不完美的检测器提供额外信息；
4. **经济最终性**：不追求严格终止，用矿工/验证者的经济利益让"回滚"变得极贵。

> **注意**：FLP 说的是**确定性**算法。比特币的 PoW 是随机过程，且只提供概率最终性；它绕开了 FLP 的前提，而不是"证明 FLP 错了"。

### 2.2 CAP 与 PACELC

**CAP**（Brewer 2000；Gilbert & Lynch 2002 形式化）：一个分布式系统最多只能同时满足以下三项中的两项：

- **C**（Consistency）：线性一致性，读到的总是最新写入；
- **A**（Availability）：每个未故障节点都能在有限时间内响应；
- **P**（Partition tolerance）：网络分区时系统仍能运行。

关键澄清：**P 不是可选项**。网络分区是现实，任何跨机房系统都必须容忍分区。CAP 真正说的是：

> 当分区发生时，你必须在 C 和 A 之间做选择。

区块链的取舍因层而异：

- **比特币**：分区时继续出块，可能产生两条链；之后按最重链合并。它偏向 **A + 最终一致性**，不是线性一致。
- **Tendermint / PBFT**：失去 $2f+1$ 投票就停止出块/最终化。它偏向 **C + 安全**，牺牲活性。
- **以太坊**：出块可以继续，但**最终性**需要 $2/3$ 质押；最终性停摆时，链仍在增长，只是确认变弱。

**PACELC** 是 CAP 的扩展：**P**artition 时在 **A** 和 **C** 之间选；**E**lse（无分区时）在 **L**（延迟）和 **C**（一致性）之间选。公链在无分区时也通常不提供线性一致：一笔交易要等几个块才"感觉安全"，这是延迟与一致性之间的连续权衡。

### 2.3 复制状态机与 quorum

共识协议的目标是实现**复制状态机（replicated state machine）**：

$$
\text{state}_{i+1} = \text{apply}(\text{state}_i,\ \text{tx}_i)
$$

只要所有节点以**相同顺序**执行**相同交易**，且 `apply` 是确定性的，它们就会得到相同状态。于是问题化为：**对一串交易的全序达成一致**（total-order broadcast）。

BFT 协议用 **quorum（法定人数）** 来保证安全：任何两个 quorum 必须至少有一个诚实节点重叠，否则两组人可以各自提交冲突的决定。设节点数 $n$，拜占庭节点最多 $f$，quorum 大小为 $q$：

$$
\underbrace{2q - n}_{\text{两个 quorum 的最小交集}} \ge f + 1
\quad\Longrightarrow\quad
q \ge \frac{n+f+1}{2}
$$

取 $n = 3f+1$，得到 $q = 2f+1$。手算例子：$n=4, f=1$，两个 quorum 各 3 个节点，最小交集 $3+3-4=2$，其中至少 1 个诚实；若 $n=3, f=1$，两个 quorum 各 2 个，交集可能只有 1 个，且恰好是骗子——安全无法保证。

## 3. 拜占庭容错：PBFT、HotStuff、Tendermint

### 3.1 为什么是 $n \ge 3f+1$

假设 $n \le 3f$。把节点分成三组，每组不超过 $f$ 个；拜占庭节点可以同时"参与"两个不同的 quorum，向两边发送互相矛盾的消息。两个 quorum 的交集最多 $f$ 个节点，可能全是骗子，于是两组诚实节点会接受冲突的决定。

反过来，若 $n \ge 3f+1$，取 $q=2f+1$：任意两个 quorum 的交集至少

$$
2(2f+1) - (3f+1) = f+1
$$

个节点，其中至少 1 个诚实。这就是 BFT 安全性的核心。

| 已知 $f$ | 最少节点 $n=3f+1$ | quorum $2f+1$ |
|---|---|---|
| 1 | 4 | 3 |
| 4 | 13 | 9 |
| 33 | 100 | 67 |

> 注意：$n=100$ 时最多容忍 $f=\lfloor(100-1)/3\rfloor=33$ 个拜占庭节点；quorum 是 67，不是 51。

### 3.2 PBFT（Castro & Liskov, 1999）

PBFT 分三阶段：**Pre-prepare**（主节点分配序号并广播）、**Prepare**（收到 $2f+1$ 个 prepare 后进入 prepared）、**Commit**（收到 $2f+1$ 个 commit 后执行）。主节点作恶或掉线时通过 **view change** 换主；安全性不依赖同步，但活性依赖部分同步。消息复杂度 $O(n^2)$，适合几十个验证者，不适合上千个。

### 3.3 Tendermint

Tendermint 按固定轮次运行：**Propose**（轮值 proposer 出块）→ **Prevote**（收到 $2f+1$ 个 prevote，即 **polka**，节点锁定该区块）→ **Precommit**（收到 $2f+1$ 个 precommit 后提交）。提交即**即时最终性**，锁定防止同一高度提交两个区块；若超过 $1/3$ 节点离线，链会**停止**而不是分叉。Cosmos 生态大量使用 Tendermint 及其后继 CometBFT。

### 3.4 HotStuff

HotStuff（Yin et al., 2019）为大规模 BFT 设计：用**阈值签名**把 $n$ 个签名聚合为一个，通信复杂度从 $O(n^2)$ 降到 $O(n)$；采用**链式**结构，连续三个区块都获得 quorum certificate 时提交最早那个；视图切换只需 $O(n)$ 消息。其思想被 Diem（Libra）及许多新链采用，HotStuff-2 进一步把提交延迟降到两轮。

### 3.5 对比

| 协议 | 故障阈值 | 最终性 | 每轮消息 | 成员 | 典型场景 |
|---|---|---|---|---|---|
| PBFT | $f < n/3$ | 即时 | $O(n^2)$ | 许可 | 联盟链、小验证者集 |
| Tendermint | $f < n/3$ | 即时 | $O(n^2)$ | 许可/质押 | Cosmos |
| HotStuff | $f < n/3$ | 即时（三连链） | $O(n)$（聚合签名） | 许可/质押 | Diem、新型 L1 |
| Nakamoto (PoW) | $q < 1/2$ | 概率 | 广播 | 无许可 | 比特币 |
| Gasper (PoS) | $f < 1/3$（按质押） | 约 2 epoch | 聚合 attestation | 无许可（质押） | 以太坊 |

## 4. 中本聪共识：PoW 与概率最终性

### 4.1 工作量证明

矿工不断改变区块头中的 `nonce`，使

$$
H(\text{header}) < \text{target}
$$

目标值越小，难度越大。若 target 对应 $D$ 次期望哈希，则

$$
D = \frac{2^{256}}{\text{target}}, \qquad
P(\text{一次成功}) = \frac{1}{D}
$$

比特币每 **2016 个区块**调整一次难度，目标是平均 **10 分钟**一块。算力上升时，target 下降（难度上升），把出块时间拉回 10 分钟。

### 4.2 分叉选择：最重链，不是最长链

网络延迟会产生分叉。节点需要一条规则选择"哪条链是主链"。比特币的规则是**累计工作量最大（most cumulative work）**，俗称"最长链"。两者在难度恒定时等价；难度变化时，**更短的链可能更重**。

一个极简实现：

```js
import { createHash } from 'node:crypto';
const H = (s) => createHash('sha256').update(s).digest();
// 教学用：十六进制前导 0 的个数表示难度
function meetsTarget(header, difficulty) {
  return H(header).toString('hex').startsWith('0'.repeat(difficulty));
}
// 累计 work 最大者胜；平局按哈希字典序，模拟确定性的 first-seen
function chooseTip(blocks) {
  return blocks.reduce((best, b) =>
    b.cumWork > best.cumWork || (b.cumWork === best.cumWork && b.hash < best.hash) ? b : best
  );
}
```

**为什么不能只看高度？** 攻击者可以生产大量低难度区块，制造一条"更长但更轻"的链。按累计工作量选择，才需要真正付出算力。Lab 2.1 会构造一条 4 块 / work=64 的链 A 和一条 3 块 / work=768 的链 B，让你看到两种规则选出不同的结果。

### 4.3 双花概率与确认数

设攻击者算力比例为 $q$，诚实网络为 $p=1-q$。商家等待 $z$ 个确认后发货。攻击者在同一父块上私下挖一条链。白皮书用一个 Poisson 近似：在诚实链增长 $z$ 块的时间里，攻击者挖到的块数

$$
K \sim \text{Poisson}(\lambda), \qquad \lambda = z\frac{q}{p}
$$

若 $K > z$，攻击者链已经更长，直接成功；若 $K \le z$，他还落后 $z-K$ 块，从落后 $d$ 块最终追平的概率是 $(q/p)^d$（赌徒破产）。因此

$$
P(\text{成功}) = 1 - \sum_{k=0}^{z}
\frac{\lambda^k e^{-\lambda}}{k!}
\left(1 - \left(\frac{q}{p}\right)^{z-k}\right),
\qquad \lambda = z\frac{q}{p}
$$

**手算示例：$q=0.1$，$z=6$。** 此时 $p=0.9$，$\lambda = 6 \times 0.1/0.9 = 0.6667$。Poisson 权重与各项如下：

| $k$ | $P(K=k)$ | $(q/p)^{6-k}$ | 该项 |
|---|---|---|---|
| 0 | 0.5134 | $1.88\times10^{-6}$ | 0.5134 |
| 1 | 0.3423 | $1.69\times10^{-5}$ | 0.3423 |
| 2 | 0.1141 | $1.52\times10^{-4}$ | 0.1141 |
| 3 | 0.02535 | $1.37\times10^{-3}$ | 0.02532 |
| 4 | 0.004226 | $1.23\times10^{-2}$ | 0.004173 |
| 5 | 0.000563 | $0.1111$ | 0.000501 |
| 6 | $6.27\times10^{-5}$ | 1 | 0 |

求和约 0.999757，故 $P \approx 2.43\times10^{-4} = 0.0243\%$。也就是说，**在攻击者只有 10% 算力时，6 个确认已经把双花概率压到约万分之 2.4**。

但当 $q=0.3$ 时，同样的 6 个确认，公式给出 **13.2%**；$q=0.4$ 时是 **50.4%**。所以"6 个确认"不是普适安全常数。

| $q$ | $z=1$ | $z=3$ | $z=6$ | $z=10$ | $z=16$ |
|---|---|---|---|---|---|
| 0.1 | 20.46% | 1.317% | 0.0243% | $1.24\times10^{-6}$ | — |
| 0.3 | 62.78% | 32.46% | 13.21% | 4.166% | 0.762% |
| 0.4 | 82.89% | 66.42% | 50.40% | 35.998% | — |

> **更精确的模型**：诚实链挖到 $z$ 块所需的时间本身是随机的，因此攻击者块数 $K$ 精确服从**负二项分布**，而不是 Poisson。Poisson 只是均值相同的近似。Lab 2.2 会同时给出模拟值、精确负二项值与白皮书公式，你会看到公式通常略偏乐观（例如 $q=0.3,z=6$ 精确值约 15.6%）。做风险预算时应留安全边际。

### 4.4 自私挖矿

自私挖矿（Eyal & Sirer, 2014）：矿工发现区块后先不广播，而是私藏，等诚实矿工浪费算力后再择机发布，从而获得更多块奖励。设攻击者算力比例 $\alpha$，诚实矿工在"平局"时选择攻击者链的比例为 $\gamma$，则自私挖矿有利可图的阈值是

$$
\alpha > \frac{1-\gamma}{3-2\gamma}
$$

手算：$\gamma=0$ 时阈值 $1/3 \approx 33.3\%$；$\gamma=0.5$ 时 $0.5/(3-1)=25\%$；$\gamma=1$ 时趋近 0。也就是说，在这个模型里，**不到 50% 的算力也可能通过扣块获利**。现实中自私挖矿的收益还受网络传播、矿池策略、难度调整和区块奖励价值影响，实际是否普遍存在仍有争议。

### 4.5 51% 能做什么，不能做什么

拥有超过 50% 算力（严格说是能持续比诚实网络更快出块）可以**双花自己的币**（先购物，再重组链把付款交易替换掉）、**审查交易**、**做深度重组**、**挖空块**。但不能**伪造他人签名**（算力不能破解 ECDSA）、**直接偷走他人的币**，也不能**单方面改变共识规则**——规则变更需要节点、矿工、交易所、用户的社会共识（见 §7 的 2013 年分叉）。而且 51% 是一个**持续成本**：要维持多数算力，需要持续支付硬件、电力和机会成本；对高价值资产，攻击成本可能高于收益。

## 5. PoS 与 Gasper

### 5.1 验证者与质押

以太坊 PoS 中，参与者质押 ETH 成为**验证者（validator）**：

- 每个验证者至少 **32 ETH** 有效余额；Pectra（2025）的 EIP-7251 允许 0x02 凭证的验证者承载最高 **2048 ETH** 有效余额（MaxEB），减少验证者数量；
- **slot** = 12 秒，**epoch** = 32 个 slot = 6.4 分钟；
- 每个 epoch 有 proposer 出块，其他验证者提交 **attestation**（对 head、source、target 的投票）；
- 质押可以退出，但有排队与延迟；罚没（slashing）会强制退出。

截至 2026-11，质押总量与验证者数量以 [beaconcha.in](https://beaconcha.in/) 等官方数据源为准；协议常数（12 秒 slot、32 slot epoch、32 ETH 最小单位）相对稳定。

### 5.2 LMD-GHOST + Casper FFG = Gasper

Gasper 是以太坊共识层的组合：

- **LMD-GHOST**（Latest Message Driven Greediest Heaviest Observed SubTree）负责**分叉选择**：每个验证者根据自己收到的最新 attestation，选择累计投票权重最大的子树作为 head；
- **Casper FFG**（Friendly Finality Gadget）负责**最终性**：每个 epoch 对 checkpoint 投票；当某个 checkpoint 获得 **2/3 总质押**的 source/target 投票时被 **justified**；连续两个 epoch 被 justified 后，前一个 checkpoint 被 **finalized**。

因此以太坊的最终性时间约为

$$
2 \times 32 \times 12\text{ s} = 768\text{ s} = 12.8\text{ 分钟}
$$

在最终化之前，交易只有概率最终性；最终化之后，回滚需要至少 1/3 质押被罚没，成本极高。

### 5.3 罚没（slashing）

验证者被罚没的两种主要行为：

1. **双重投票**：在同一 target epoch 对两个不同 checkpoint 投票；
2. **环绕投票（surround vote）**：投票的 source/target 区间包围了之前的投票。

罚没包括**最低惩罚**（约 $1/32$ 有效余额，32 ETH 验证者约 1 ETH）、**相关性惩罚**（多人同时被罚没时按比例放大，最高可接近全部质押）、**强制退出**，以及 **inactivity leak**（链长时间无法最终化时，未投票验证者被持续扣减，直到在线质押恢复到 $2/3$）。

### 5.4 无利害关系、长程攻击与弱主观性

**无利害关系（nothing at stake）**：在朴素的 PoS 中，验证者在多条分叉上同时签名几乎没有边际成本（除了机会成本），因此可能不愿只选一条链，导致分叉难以收敛。以太坊的应对是**罚没**（冲突签名付出真实代价）、**LMD-GHOST**（最新投票决定 head）与**最终性**（已 finalize 的区块极难回滚）。

**长程攻击（long-range attack）**：攻击者获取很久以前（甚至已退出）的验证者私钥，从创世附近重建一条替代链。由于旧密钥当时确实有权签名，新节点仅看密码学证据无法分辨。应对包括**弱主观性**（新节点需要一个最近的可信 checkpoint 作为同步起点，窗口称为 weak subjectivity period）、**checkpoint sync**（从最近的 finalized checkpoint 开始，而不是从创世重放）以及**最终性 + 罚没**。

"弱"主观性意味着：与 PoW 不同，PoS 新节点的"同步"不仅需要当前数据，还需要一点**最近的社会共识**。这不是缺陷，而是 PoS 安全模型的一部分；代价是新节点必须信任一个较新的起点。

### 5.5 最终性对比

| | PoW（比特币） | BFT / Gasper（以太坊） |
|---|---|---|
| 出块权 | 算力 | 质押 |
| 分叉选择 | 最重链 | LMD-GHOST |
| 最终性 | 概率，随确认数增加 | 确定性，约 12.8 分钟 |
| 分区时 | 可能分叉，之后合并 | 可能停止最终化 |
| 主要攻击成本 | 51% 算力 | 1/3 质押被罚没 + 社会协调 |
| 新节点同步 | 从创世/检查点，无需信任最近状态 | 需要弱主观性 checkpoint |

## 6. 数据可用性：区块头有效，数据却不见了

一个区块可能**头有效、交易数据却不可得**：出块者广播了区块头，但扣住了区块体。全节点无法执行交易，轻客户端更无法验证。这就是**数据可用性（data availability, DA）问题**。**有效性（validity）**问的是状态转换是否正确，**可用性（availability）**问的是区块数据是否真的发布、让任何人可以下载并重建状态；两者缺一不可。Rollup 把交易数据发回 L1，如果 L1 的数据不可用，用户就无法从 L2 状态中退出或重建（M13 详述）。

**解决方案的核心是纠删码 + 随机采样**：出块者用 **Reed–Solomon 纠删码**把区块数据扩展成 $2n$ 个 chunk，任意 $n$ 个 chunk 就能重建全部数据；轻客户端随机抽取若干 chunk，若出块者藏了超过一半的数据，抽样命中的概率随样本数指数下降；**数据可用性采样（DAS）** 让轻客户端用很少的带宽获得高置信度的可用性保证；**KZG 承诺**让节点验证 chunk 属于正确的纠删码多项式，防止出块者伪造。

以太坊的 **EIP-4844 blob**（Dencun, 2024）为 L2 提供了廉价的临时数据空间；**PeerDAS**（Fusaka, 2025）把 DAS 引入共识层，为未来的 danksharding 铺路。具体 blob 数量与参数以 [EIP-4844](https://eips.ethereum.org/EIPS/eip-4844)、[EIP-7594](https://eips.ethereum.org/EIPS/eip-7594) 和最新路线图为准（截至 2026-11）。

## 7. 案例：共识在现实中如何失效

### 7.1 比特币 2013 年分叉

2013 年 3 月 11 日，比特币 v0.8 与 v0.7 对同一个区块（高度 225430）产生分歧：v0.8 使用 BerkeleyDB 的方式改变，接受了一个 v0.7 认为无效的区块，链分裂成两条。多数算力在 v0.8 一侧，但开发者建议矿工**降级到 v0.7**，以回到共同规则。约 6 小时后，多数矿工完成降级，链重新合并。教训：**共识不仅是数学，也是实现**——一个数据库锁的细节就能让网络分叉；**社会共识是最后的安全层**；客户端多样性与谨慎的版本发布至关重要。

### 7.2 以太坊 The Merge（2022-09-15）

以太坊从 PoW 切换到 PoS。触发点是**终端总难度（TTD）**：

$$
\text{TTD} = 58750000000000000000000
$$

执行层达到该总难度后，共识层接管出块。合并后：出块不再依赖算力，验证者按质押参与；最终性从概率变为约 12.8 分钟的确定性最终化；据以太坊基金会估计，能耗下降约 **99.95%**。教训：共识机制的切换是**社会 + 工程 + 密码学**的联合行动；fork choice、最终性、客户端同步、交易所支持必须同时到位。

### 7.3 最终性停摆（2023-05）

2023 年 5 月，Prysm 客户端的一个 fork-choice 缺陷导致信标链短暂停止最终化。链仍在出块，但一段时间内没有新的 finalized checkpoint。客户端多样性帮助网络恢复，未发生链分裂。

教训：**活性故障不等于安全故障**。最终性停摆会让确认变慢，但只要 $2/3$ 质押最终恢复在线，链可以继续；这与 PoW 的深度重组是不同性质的风险。

## 8. CS / 工程视角

| 共识概念 | 已有 CS 概念 | 工程启示 |
|---|---|---|
| 复制状态机 | 确定性状态机 + 日志复制 | 交易执行必须确定性；重放日志可恢复状态 |
| quorum | 分布式读写 quorum、Raft 多数派 | 任意两个 quorum 必须相交；交集大小决定故障阈值 |
| PBFT / Tendermint | 两阶段提交、Paxos/Raft 的 Byzantine 版本 | 2PC 怕协调者故障；BFT 用 quorum 证书与视图切换替代单点 |
| 最终性 | 数据库 commit、事务隔离 | finalized ≈ 不可回滚的 commit；之前只是"未提交" |
| 分叉选择 | 冲突解决、last-writer-wins | 需要确定性的比较函数（最重链、LMD-GHOST） |
| 重组（reorg） | 回滚与补偿事务 | 索引器、交易所必须处理 reorg；确认数是一种"延迟提交" |
| 数据可用性 | 备份、纠删码、审计 | 仅有哈希承诺不够；必须保证数据可被下载 |
| 客户端多样性 | 冗余、异构系统 | 单客户端缺陷可能变成全网 liveness 故障 |
| 形式化验证 | TLA+、Coq、模型检查 | 共识协议适合形式化；实现仍需测试与模糊测试 |

一个实用的工程习惯：**把"最终性"当成一个可观测指标**。索引器应记录 `finalized` 高度与 `head` 高度的差值；交易所应根据资产价值设置确认数；跨链桥应等待源链最终化，而不是仅看区块头。

## 9. 常见误区

1. **"CAP 只能三选二"** → P 是网络条件，不是可选项；分区时在 C 与 A 之间选。公链通常不是线性一致，而是最终一致。
2. **"51% 算力可以偷走别人的币"** → 不能伪造签名；可以双花自己的币、审查、重组。
3. **"PoS 有无利害关系问题，所以 PoS 不安全"** → 朴素 PoS 确实有；以太坊用罚没、最终性、弱主观性缓解。无利害关系不是"无解"，而是需要显式设计。
4. **"6 个确认绝对安全"** → 概率随攻击者算力变化；$q=0.3$ 时 6 个确认的公式值约 13%，精确模型约 15.6%。
5. **"BFT 的 3f+1 和 PoW 的 51% 是一回事"** → 故障模型不同：BFT 容忍 $<1/3$ 拜占庭，PoW 容忍 $<1/2$ 算力；最终性类型也不同。
6. **"最终性意味着永远不可逆"** → 协议层 finality 很强，但社会层仍可能通过硬分叉改变历史（如 2016 年 DAO 事件）；最终性是工程与经济意义上的，不是物理定律。
