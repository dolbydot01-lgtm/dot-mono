```text
  nonce 重用：c1=6881146174…, c2=1070555633…
  恢复私钥 == 真实私钥？true（Schnorr 的线性结构使泄露更直接）
```

```text
── 4. 组合：授权集合中的成员证明 + nullifier 防重放 ────────────────────
  授权集合根 900c507811e569cd…，证明成员 #3
  Merkle 成员证明：true
  Schnorr 知识证明：true
  nullifier = H(secret || action) = 3f0e08e5eedfeb29…
  第一次领取：接受，记录 nullifier
  第二次领取（重放）：拒绝（nullifier 已使用）
```

### 这个实验在做什么

1. **Merkle 树**：叶子用 `SHA-256(0x00 || data)`，内部节点用 `SHA-256(0x01 || left || right)`，做域分离。奇数节点提升到下一层。证明包含兄弟哈希与方向；验证者重算根。
2. **字典攻击**：承诺 `H(salt || PIN)` 隐藏了 PIN，但 PIN 只有 10,000 种可能；攻击者可以枚举。128 位随机秘密的搜索空间约 `2^128`，以每秒 `1e9` 次哈希计算，期望时间约 `1.08e22` 年。
3. **Schnorr + FS**：`c = H(R || P || context)`；证明 `(R, z)`；验证 `zG = R + cP`。模拟器可以选 `c,z` 反算 `R`，所以验证方程成立；但真实哈希不会输出模拟器想要的 `c`，所以模拟 transcript 不能通过 FS 验证。这展示了"零知识（可模拟）"与"可靠性（挑战必须绑定）"的张力。
4. **nonce 重用**：同一个 `k` 下两个不同挑战 `c1,c2` 产生 `z1,z2`，可解出 `x=(z1−z2)/(c1−c2)`。
5. **成员 + nullifier**：Merkle 证明隐藏了私钥，但泄露了"是哪一个成员"；nullifier 防双花，但不提供匿名性。真正的匿名需要把 Merkle 路径检查放进 zk 电路（见 Circom 参考）。

```text
  A(x) = 10x + 94
  B(x) = 99x + 5
  C(x) = 4x + 5
  Z(x) = x^2 + 98x + 2（在约束点 1、2 处为 0）
  H(x) = 81（商多项式，次数 ≤ n−2 = 0）

  随机点 r    A(r)  B(r)  C(r)  Z(r)   A·B−C  H·Z  成立？
  ──────────────────────────────────────────────────────────────
         0    94     5     5     2      61    61  true
         3    23   100    17     2      61    61  true
         5    43    96    25    12      63    63  true
        17    62    72    73    38      48    48  true
        42     9    22    72    24      25    25  true
```

```text
  错误 witness（z=14）：C'(x) = 5x + 4
  A·B − C' 除以 Z 的余式 = 100x + 1（非零 ⇒ 不存在商多项式 H）
  若证明者仍提交 H = 81，在 r=3、5 处检查：
    r=3: A·B−C' = 59, H·Z = 61，成立？false
    r=5: A·B−C' = 59, H·Z = 63，成立？false

  若证明者看到 r 后再编造 H(r)：
    r=3: 临时取 H(r)=80，检查通过？true
    r=5: 临时取 H(r)=47，检查通过？true
  但两个点要求不同的 H(r)（80 vs 47），而 H 的次数被限制在 0——
  所以证明者必须在挑战前承诺 H；这正是 KZG/FRI 多项式承诺的作用。
  Schwartz–Zippel：错误多项式 A·B−C−H·Z 的次数为 2，随机点命中根的概率 ≤ 2/101 = 1.980%。
```

```text
── 2. 一元 Schwartz–Zippel：随机点命中根的概率 ─────────────────────────
  P(x) = ∏(x−i), i=1..10，在 F_101 上恰有 10 个根
  抽样 20,000 次（种子 0x142027）：命中 1947 次
  模拟命中率 9.735%，理论值 d/|F| = 10/101 = 9.901%
  相对误差 1.676%

  域大小对可靠性上界的影响（d = 10）：
  |F|            单次上界        重复 2 次       重复 3 次
  ────────────────────────────────────────────────────────────
  101              9.900990%    0.980296049%  0.097059014793%
  1009             0.991080%    0.009822401%       9.735e-5%
  65537            0.015259%       2.328e-6%      3.553e-10%
  2^61−1          4.337e-16%      1.881e-33%      8.157e-51%
```

```text
── 4. FRI 式抽查：抽 k 个点能发现多少篡改？ ───────────────────────────
  1% 篡改：1024 个求值点中篡改 10 个
  k     精确检测率      近似 1−(1−t/n)^k   模拟检测率
   40    32.985209%          32.466395%     32.740%
   80    55.833551%          54.392122%     56.280%
  160    81.862414%          79.199214%     80.840%
  320    97.688012%          95.673273%     97.900%

  对 1% 篡改，要把漏检概率压到 0.1%，约需 k = 704 次查询。
```

### 这个实验在做什么

1. **QAP**：把 `t=x*x; z=t+y` 两条约束插值成 `A,B,C,Z`；正确 witness 满足 `A·B−C=H·Z`。错误 witness 使余式非零，随机点检查失败。
2. **自适应作弊**：如果证明者看到挑战点后才选 `H(r)`，可以在每个点单独满足等式；但同一个低次多项式不能同时在两个点取两个不同的值。多项式承诺阻止这种事后更改。
3. **Schwartz–Zippel**：`Pr[P(r)=0] ≤ d/|F|`；域越大、次数越小，漏检概率越低；重复查询指数级放大可靠性。
4. **多变量版本**：`D(x,y)=(x−1)(y−2)` 的总次数为 2；模拟命中率约 2.030%，精确值 `1−(100/101)²=1.970%`，上界 `2/101=1.980%`。
5. **FRI 抽查**：精确检测率是超几何分布（无放回），近似式假设有放回；两者在小抽样比例下接近。1% 篡改、`k=40` 时约 33% 检测率；要把漏检压到 0.1%，需要约 704 次查询。FRI 通过折叠把次数减半，使每轮查询都约束全局低度性，而不是只查大表。

## Circom 参考电路（只读）

### `labs/circuits/merkle-proof.circom`

```circom
template Withdrawal(depth) {
    signal input secret;
    signal input nullifier;
    signal input pathElements[depth];
    signal input pathIndices[depth];
    signal input root;              // public
    signal output nullifierHash;    // public
    ...
}
component main {public [root]} = Withdrawal(20);
```

要点：

- `leaf = Poseidon(secret, nullifier)`；`root` 是公开输入；`nullifierHash = Poseidon(nullifier)` 是公开输出。
- `pathIndices[i] * (pathIndices[i] - 1) === 0` 强制方向为 0/1；删掉会引入约束不足。
- 20 层可容纳 `2^20 ≈ 104 万` 个叶子。
- 真实 Tornado 还固定面额、维护 root 历史、nullifier 集合、relayer 与合规策略；电路只负责"成员性 + nullifier 正确"。

### `labs/circuits/qap-demo.circom`

```circom
template QapDemo() {
    signal input x;
    signal input y;
    signal output z;
    signal t;

    t <== x * x;   // 约束 1
    z <== t + y;   // 约束 2（加法不增加乘法约束）
}
component main = QapDemo();
```

它与 Lab 14.2 第 1 节是同一个电路。`<==` 同时赋值并生成约束；Circom 编译器会把它转成 R1CS。注意：加法本身通常不增加乘法约束，但会产生线性约束/信号关系；实际约束数要以 `snarkjs r1cs info` 为准。

## 常见问题

**Q：为什么 Lab 14.1 的 Merkle 根每次运行都一样？**
A：叶子、盐、密钥都由固定种子或固定字符串派生；没有使用系统随机数。这是为了可复现，不代表真实协议可以复用这些值。

**Q：为什么模拟器能生成通过验证方程的 transcript，却不算伪造？**
A：因为它不能通过 Fiat–Shamir 的挑战检查：真实哈希输出不可预测，模拟器无法让 `H(R||P||ctx)` 等于它预先选的 `c`。在随机预言机模型里，模拟器可以"编程"哈希，所以零知识性成立；真实世界没有这种能力。

**Q：为什么 QAP 在 `r=0` 也通过？**
A：`A·B−C` 与 `H·Z` 作为多项式相等，因此在任何点都相等，包括 `r=0`。安全性不依赖某个特定点，而依赖证明者无法预测随机点且无法事后更改承诺。

**Q：为什么 FRI 的精确检测率与近似式不同？**
A：精确式是无放回抽样（超几何分布），近似式假设每次独立、有放回。当 `k` 远小于 `n` 时两者接近；`k` 很大或篡改比例很高时差异更明显。

**Q：Circom 电路能直接跑吗？**
A：不能。本机没有 `circom`/`snarkjs`，电路只作阅读参考。要实际编译，需要安装 Circom 2.1.x、circomlib，并准备 powers-of-tau 文件；命令示例见讲义 §3。
