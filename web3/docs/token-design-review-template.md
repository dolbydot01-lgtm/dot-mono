# Token Design Review 模板

> 用法：复制到 `capstone/docs/token-design-review.md`。目标不是判断"这个币会不会涨"，而是检查代币的经济功能、价值捕获、激励相容与风险是否自洽。配合 M8、M7、M18 阅读。

## 0. 一页结论

| 字段 | 内容 |
|---|---|
| 项目 | 名称 / 版本 / 日期 |
| 代币 | 符号、总量、当前流通量、合约地址（测试网） |
| 一句话定位 | 它解决什么问题？ |
| 核心结论 | 设计是否自洽？最大风险是什么？ |
| 建议 | 保留 / 修改 / 重新设计（说明理由） |

## 1. 代币的功能

勾选并解释每一种功能，避免"什么都想要"：

- [ ] 支付手段（购买服务 / 手续费）
- [ ] 治理权（投票、提案、委托）
- [ ] 现金流权（分红、回购、费用分配）
- [ ] 工作 / 质押凭证（验证者、节点、保险）
- [ ] 准入权（白名单、API、会员）
- [ ] 激励补贴（流动性挖矿、任务奖励）
- [ ] 纯粹的 Meme / 社区身份

对每种功能回答：**没有代币能不能实现？** 如果能，代币的必要性是什么？

## 2. 供给设计

| 项目 | 数值 / 规则 |
|---|---|
| 初始总量 | |
| 最大总量 | 固定 / 通胀 / 通缩 |
| 年化通胀率 | 当前 / 目标 |
| 释放曲线 | 线性 / 指数 / 里程碑 |
| 分配 | 社区、团队、投资人、金库、流动性（% + 解锁期） |
| 回购 / 销毁 | 触发条件、资金来源、执行方式 |

**检查**

- 未来 12 / 36 个月的流通量是多少？用表格或图；
- 解锁高峰是否与激励结束、产品上线撞车？
- 通胀补贴停止后，协议还能留住多少 TVL / 用户？
- 回购资金来自真实收入还是新发代币？

## 3. 需求与价值捕获

| 问题 | 回答 |
|---|---|
| 谁必须买 / 锁定代币？ | |
| 为什么现在买，而不是以后？ | |
| 代币捕获了协议的哪部分价值？ | 费用、MEV、抵押品、治理权…… |
| 价值捕获是自动的，还是依赖治理投票？ | |
| 如果协议收入翻倍，代币持有者如何受益？ | |

**估值交叉检查**

- DCF：协议收入 → 可分配现金流 → 贴现；说明贴现率与永续增长率假设；
- P/F、P/S：与同类协议比较，说明分子分母口径；
- 流通速度模型：`V = PQ / M`，说明为什么该模型在此处适用或不适用；
- 完全稀释估值（FDV）与流通市值的差距。

## 4. 激励与机制设计

- 激励对象是谁？他们贡献了什么？
- 激励是**雇佣资本**（逐利而来、补贴停止即走）还是**长期对齐**（锁定、声誉、治理参与）？
- 是否存在女巫攻击 / 刷量？如何识别与惩罚？
- 空投规则是否可被 sybil 批量套利？
- ve 模型的锁仓是否造成治理寡头？
- 激励预算占总量多少？可持续多少年？

## 5. 治理

- 谁可以提案、投票、执行？
- 投票权与持币量是否线性？是否有委托、二次方投票、乐观治理？
- 紧急权限（暂停、升级、参数修改）在谁手里？有无时间锁？
- 治理攻击的成本是多少？（借币 / 闪电贷 / 贿赂）
- 法律实体：基金会、DUO、离岸结构？代币是否被认定为证券？

## 6. 风险清单

| 风险 | 触发条件 | 影响 | 缓解 |
|---|---|---|---|
| 死亡螺旋 | 价格下跌 → 抵押不足 → 清算 → 进一步下跌 | | |
| 激励退出 | 补贴停止 → TVL 流失 | | |
| 治理攻击 | 借币控制投票 | | |
| 监管 | 被认定为证券 / 稳定币 | | |
| 集中度 | 少数地址持有大部分代币 | | |
| 流动性 | 深度不足、滑点大 | | |

## 7. 敏感性分析

至少做三组情景：**熊市 / 基准 / 牛市**。每组给出：

- 代币价格、流通市值、FDV；
- 协议收入、可分配现金流；
- 激励支出、金库剩余年限；
- 关键假设（用户增长、费率、TVL、波动率）。

可以用 M8 的 lab 生成表格，再把结果贴回本文件。

## 8. 结论

- 设计是否自洽？哪些部分互相矛盾？
- 代币是"必要的协调工具"还是"融资与退出工具"？
- 如果只能改一个参数，改什么？为什么？
- 给项目方的三条具体建议。
