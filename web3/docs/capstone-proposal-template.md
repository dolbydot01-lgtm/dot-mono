# Capstone Proposal 模板

> 提交给同学 / 导师之前，先用一页纸回答清楚。复制到 `capstone/proposal.md`。

## 1. 一句话

用一句话说明：**谁**在**什么场景**下，用你的系统解决**什么问题**。

## 2. 问题与动机

- 现状是什么？现有方案（中心化平台 / 其他协议）哪里不够好？
- 为什么需要区块链？如果所有参与方都信任同一个运营者，数据库是否就够了？
- 你的目标用户是谁？他们今天怎么解决这个问题？

## 3. 方案

- 核心机制（3–5 步）；
- 系统边界：哪些在链上，哪些在链下；
- 关键角色与权限；
- 与现有方案的差异（不要只写"更去中心化"）。

## 4. 成功指标

选 2–4 个**可验证**的指标，例如：

- 主路径端到端跑通（是 / 否）；
- 核心不变量在 10,000 次随机调用后仍成立；
- 在给定价格冲击下坏账 < X%；
- 索引器延迟 < Y 秒；
- 研究报告的数据可被第三方用同一 SQL 复现。

避免"用户体验好""社区活跃"这类无法验证的指标。

## 5. 范围外

明确列出**不做什么**：主网上线、真实资产、移动端、法币出入金、完整治理……范围越清楚，交付越可控。

- 使用 AI 工具的范围与验证方式。
