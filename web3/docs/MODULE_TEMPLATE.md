# 模块编写规范（Module Template）

本文件是 M2–M18 的统一写作契约。目标：每个模块都能独立学习，风格与 M0/M1 一致，且所有 JS 实验能在本机 `node` 直接运行。

## 1. 目录结构

```
modules/M{nn}-{slug}/
├── README.md              讲义
├── exercises.md           习题 + 参考答案
├── assets/                可选：图片、SVG、数据
└── labs/
    ├── README.md          实验说明、命令、预期输出、任务
    └── *.mjs              可独立运行的 Node.js 实验（ESM）

## 2. README.md 结构

每个 README 用中文，标题为 `# M{n} {中文标题}`，开头引用块：

```markdown
> 所属：Part ... ｜ 建议学时：... ｜ 截至 2026-11
> 前置：M... ｜ 后续：M...
```

必须包含以下章节（序号可调整，但内容不能缺）：

1. **学习目标**：5–7 条可检验的能力，用"能够解释 / 推导 / 实现 / 比较"开头。
2. **本章地图**：一张表，把"问题 → 工具/概念 → 在区块链中的位置 → 小节"对应起来。
3. **直觉**：先讲一个具体场景或类比，再引出术语；不要一上来堆定义。
4. **形式化 / 机制**：核心定义、公式、算法、协议流程。公式用 LaTeX `$...$` / `$$...$$`。至少一个**手算示例**。
5. **代码 / 实现**：一段可读的代码或伪代码，说明它如何落地（Solidity、JS、EVM 操作码均可）。代码要与 labs 呼应。
6. **案例 / 数据**：至少一个真实案例、历史事件或数值对比，讲清"机制在现实中如何表现"。
7. **CS / 工程视角**：按 SYLLABUS 附录 E，把本章概念对照到已有计算机知识（复制状态机、数据结构、数据库事务、系统资源计量、软件工程、可观测性等）。
8. **常见误区**：4–6 条，每条"误解 → 事实"。
9. **实践**：指向 `labs/README.md`，列出 Lab 编号与一句话目标。
10. **习题**：指向 `exercises.md`。
11. **延伸阅读**：3–6 条，优先原始论文、EIP、官方文档，附链接。

篇幅目标：README **200–400 行**。宁可把一个机制讲透，不要罗列名词。每节至少有一个具体例子或数字。

## 3. exercises.md 结构

```markdown
# M{n} 习题

> 难度：★ 基础　★★ 理解　★★★ 拓展。答案在文末，先独立思考再看。

## A. 概念题
**A1 ★** ...
...
## B. 计算题
**B1 ★★** ...（必须能手算，给出关键中间量）
...
## C. 实践 / 案例题
**C1 ★★** ...
...
## D. 讨论题（可选）
**D1 ★★★** ...

---

## 参考答案

**A1**　...
```

要求：

- 至少 **8 道题**（A 3–4、B 3–4、C 2–3），其中至少 2 道需要计算、2 道需要结合代码或真实案例。
- 每题有难度星级；参考答案必须完整，不能只写"略"。
- 计算题的数字要自洽，答案要能用手算复核；建议在写完后用 Node 快速验算。
- 题目覆盖本章的核心概念、一个常见误区、一个与前后模块的衔接点。
- 若 quiz.html 中已有该模块的预习题，题目风格与知识点要与之兼容（不必逐字复制）。

## 4. labs/README.md 结构

```markdown
# M{n} 实验：{标题}

> 安全提示：仅本地 / 测试网；不要使用真实私钥或真实资产。

## 准备
```bash
cd web3 && npm install   # 仅首次
```

## Lab {n}.1 {名称}
```bash
node modules/M{nn}-{slug}/labs/01-xxx.mjs
```
| 文件 | 内容 |
|---|---|
| `01-xxx.mjs` | ... |

预期输出（节选）：
```text
...
```

**任务**
1. ...
2. ...

## Lab {n}.2 ...
```

要求：

- 每个模块至少 **1 个可运行的 Node.js 实验**；建议 2 个。
- 实验脚本必须能用 `node <path>` 从仓库根目录直接运行，不依赖网络、不依赖 Foundry / Circom / 数据库。
- 脚本使用 ESM（`.mjs`），只使用 Node 内置模块或根目录已有依赖（`viem`、`@noble/*`）；不要新增 npm 依赖。
- 输出要有明确的结构（分节标题、数字、结论），并包含一个"思考点"或"动手改一改"。
- 涉及随机性的实验必须使用**固定种子**的可复现 PRNG（自己写一个 mulberry32 即可），并在输出中说明种子。
- 若模块涉及 Solidity，可额外提供 `labs/contracts/*.sol` + Foundry 测试，但**必须**同时提供一个不依赖编译器的 JS 实验（存储布局、选择器、ABI 编码、经济模型模拟等），确保没有 Foundry 也能学。
- 若模块涉及 Circom / snarkjs，提供 `.circom` 参考代码与命令，但 JS 实验用哈希 / Merkle 证明模拟"零知识"的核心思想，不要求安装工具链。

## 5. 代码风格

- 中文注释，解释"为什么"而不是复述语法。
- 数字用 `BigInt` 时显式标注 `n`；金额计算避免浮点误差，必要时用整数最小单位。
- 每个实验开头写：`// Lab {n}.{m} —— 一句话目标` 和运行命令。
- 不要 `console.log` 大段 JSON；用表格/分节输出，便于阅读。
- 脚本失败时抛出明确错误（`throw new Error(...)`），不要静默返回错误结果。
- 涉及金融公式的实验，输出至少一个"解析解 vs 模拟值"的对比。

- [ ] 至少一个手算示例，数字自洽。
- [ ] exercises.md ≥ 8 题，参考答案完整。
