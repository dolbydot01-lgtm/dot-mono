## M1 · 密码学哈希：三条要求，一次讲清

对应讲义：[`modules/M01-cryptography/README.md`](../modules/M01-cryptography/README.md) §1.1。

### 1. 哈希是什么？

给数据拍一张"数字指纹"：

- 任意长度的数据进去，固定长度（例如 256 位）的指纹出来；
- 同样的数据，指纹永远一样；
- 数据只改一个字符，指纹也会面目全非；
- 谁都能算，不需要密钥。

写成公式：`H: {0,1}* -> {0,1}^n`。

**先记住**：哈希不是加密。加密能解密，哈希不能倒推；公链数据本来就是公开的，哈希保证的是"没被改过"，不是"别人看不见"。

### 2. 三条核心要求

#### ① 抗原像（单向性）：看指纹，猜不出人

- 给你一个指纹 `y`，很难找到 `x` 使 `H(x) = y`；
- 只能一个一个试，256 位哈希大约要试 `2^256` 次；
- 区块链用处：地址隐藏公钥、承诺方案隐藏答案。

#### ② 抗第二原像：不能把你掉包成"同指纹"的另一个人

- 已经给你 `x`，很难再找 `x' ≠ x` 使 `H(x') = H(x)`；
- 同样大约 `2^256` 次；
- 区块链用处：交易上链后，交易 ID 不能被换成另一笔内容不同的交易。

#### ③ 抗碰撞：不能凭空造出两个"同指纹"的人

- 不指定目标，只要找到任意一对 `x ≠ x'` 且 `H(x) = H(x')` 就算赢；
- 这比前两个容易：大约 `2^(n/2)` 次。256 位哈希 → `2^128` 次；
- 区块链用处：Merkle 根、区块哈希、承诺的绑定性。能造碰撞，就能伪造"某笔交易在区块里"的证明。

| 要求 | 攻击者手里有什么 | 要找到什么 | 256 位难度 | 通俗记法 |
|---|---|---|---|---|
| 抗原像 | 一个指纹 | 对应的原数据 | `2^256` | 看指纹猜人 |
| 抗第二原像 | 一个数据 `x` | 另一个同指纹数据 | `2^256` | 不能掉包 |
| 抗碰撞 | 什么都没有 | 任意一对同指纹数据 | `2^128` | 不能造双胞胎 |

**术语对照**：抗原像 = preimage resistance = 单向性；抗第二原像 = second-preimage resistance = 弱抗碰撞；抗碰撞 = collision resistance = 强抗碰撞。

### 3. 为什么抗碰撞只有"一半安全"？——生日悖论

不用背公式，记住这个类比：

- 一年 365 天，只要 23 个人，就有超过 50% 的概率两人生日相同；
- 哈希有 `2^n` 种输出，试到大约 `2^(n/2)` 个，就很可能撞上一对。

所以：

- 128 位哈希 → 约 `2^64` 次就能撞，今天很快；
- 256 位哈希 → 约 `2^128` 次，目前不可行。

这就是"256 位哈希只有 128 位安全"的来源。**注意：这句话只针对抗碰撞；抗原像仍然是 256 位。**

更一般地：把 `m` 个不同输入随机映射到 `n` 种输出（`m ≤ n`），至少一对冲突的概率是

```text
P = 1 - n(n-1)...(n-m+1) / n^m
  ≈ 1 - exp(-m(m-1) / (2n))
  ≈ m(m-1) / (2n)        （当 m 远小于 √n）
```

- 期望冲突对数：`m(m-1)/(2n)`；
- 50% 冲突阈值：`m ≈ 1.177√n`；
- 若 `m > n`，鸽笼原理保证冲突概率为 **100%**（这时不是概率问题）。

例：`n = 2^256, m = 2^128` 时，冲突概率约 **39.3%**；要到 50%，需要 `m ≈ 1.177 × 2^128`。

### 4. 三个最容易混的点

1. **碰撞一定存在，只是找不到。** 输入无限、输出有限，鸽笼原理保证一定有碰撞；密码学只要求"找起来难"。
2. **三条要求不是一回事。** 抗碰撞最强，能推出抗第二原像；但它和抗原像一般互不推出。地址主要靠抗原像（还要私钥难求），Merkle 根主要靠抗碰撞。设计时要写清楚依赖哪条。
3. **哈希安全 ≠ 用法安全。** 算法没坏，用法可能出事：
   - Merkle 树不给叶子和内部节点加不同前缀，内部节点就能被当成叶子，伪造一棵根相同的树。修复：叶子 `H(0x00‖d)`，内部节点 `H(0x01‖L‖R)`；
   - 比特币 Merkle 树在奇数节点时复制最后一个，导致 `[a,b,c]` 和 `[a,b,c,c]` 根相同（CVE-2012-2459）；
   - SHA-256 有长度扩展问题，别用 `H(secret‖msg)` 当 MAC，要用 HMAC；
   - 函数选择器只取 Keccak 前 4 字节（32 位），生日碰撞只要约 `2^16` 次，所以会出现 selector 冲突——不是 Keccak 坏了，是截断太短。

### 5. 区块链里用在哪

| 用途 | 怎么用 | 依赖哪条性质 |
|---|---|---|
| 地址 | 公钥的 Keccak 哈希取后 20 字节 | 抗原像（+ 私钥难求） |
| 交易 ID | 整笔交易的 Keccak 哈希 | 抗碰撞、抗第二原像 |
| 区块哈希 | 区块头的 Keccak 哈希 | 抗碰撞（+ 挖矿） |
| Merkle 根 | 交易两两哈希到根 | 抗碰撞 |
| 哈希承诺 | `H(值 ‖ 随机数)` | 隐藏靠抗原像，绑定靠抗碰撞 |
| 挖矿 | 找随机数让区块哈希小于目标 | 谜题友好 |
| 密码存储 | 加盐 + 慢哈希（Argon2/scrypt/bcrypt） | 抗原像，不是抗碰撞 |

### 6. 两条工程性质

- **雪崩效应**：输入改 1 位，输出大约一半的位会翻转。用来检查哈希实现有没有明显结构。
- **谜题友好**：挖矿时只能一个一个试随机数，没有捷径——这是 PoW 的基础。

### 7. 数字有多大？

按每秒 `10^18` 次计算：

| 次数 | 大概感觉 |
|---|---|
| `2^64` | 18 秒 |
| `2^80` | 14 天 |
| `2^128` | 约 `10^13` 年（约 780 个宇宙年龄） |
| `2^256` | 天文数字，不用算 |

量子计算机（理想化模型）：Grover 把"猜原像"降到 `2^(n/2)`，256 位仍有 128 位量子安全；量子碰撞搜索约 `2^(n/3)`，256 位约 `2^85`，仍然很大。所以长期系统用 256 位。

### 8. 自测

1. 256 位哈希，抗碰撞、抗原像、抗第二原像各是多少位安全？
2. 为什么"抗碰撞"比"抗第二原像"更容易攻破，却说它更强？
3. Merkle 树为什么要在叶子和内部节点前加不同的字节？
4. 以太坊用的是 SHA3-256 吗？
5. 交易上链后不能被替换，主要靠哪条性质？

**参考答案**

1. 抗碰撞 128 位；抗原像、抗第二原像 256 位。
2. "更强"指它是更严格的假设：抗碰撞要求任意一对都找不到，自然也能防住给定 `x` 的第二原像。但碰撞攻击不需要指定目标，可以用生日攻击，所以代价只有 `2^(n/2)`，而第二原像要 `2^n`。
3. 防止内部节点哈希 `H(L‖R)` 被当成"内容为 `L‖R` 的叶子"的哈希，从而伪造一棵根相同的树。这叫域分离。
4. 不是。以太坊用 Keccak-256（原始提交版），和 NIST SHA3-256 的填充规则不同、输出不同。
5. 抗第二原像；签名同时保证内容经过授权。
